# Plan: the panel's state matches what actually happened

## Approved decisions, carried over

Self-contained: everything needed to implement this is below.

**Why:** four defects of one shape -- the panel holding a state that no
longer matches reality. A write that landed while its form was closing is
never reflected; a stale answer can close a form the user has reopened and
is typing into; naming a flake input survives a tab change and swallows the
keyboard on an unrelated tab; one `Process` shared by two readers silently
drops one of them; and a process that dies without answering leaves the
panel refusing every later write.

**The four decisions taken at spec time:**

1. **One line, not a token**, for the stale-response guard. `commit()`
   refuses to start while `model.busy` and `busy` only clears on an answer,
   so two writes to the same option cannot overlap and there is never more
   than one outstanding response to disambiguate.
2. **Refresh on the late path, no message.** A write that landed must reach
   the panel even when nobody is watching; a message about a closed form
   would land on whatever the user is doing now.
3. **Cancel naming in `setTab`, with a new `namingAbandoned()` signal**, so
   `Menu.qml` can tell "left the tab" (drop the half-typed name) from ESC
   (`Menu.qml:214`, which deliberately restores a hand-typed flakeref).
4. **`onExited` on three processes, not seven** -- only where a failure
   strands a flag that blocks later work.

**Verified while planning, and load-bearing for decision 1:** a write can be
started from exactly two places, `OptionForm.qml:257` and
`PkgModel.qml:321`, and both are guarded by `busy` (`:250`, `:317`). `busy`
is set at `:254`/`:318` and cleared only at `:95`/`:219`, on a response.
The interlock holds.

**But it couples 1 to 4.** Because `busy` clears *only* on a response, a
write process that dies silently leaves it stuck forever -- and then the
interlock decision 1 relies on is jammed rather than merely satisfied, and
every later write is refused "still writing". Step 5 is therefore not an
independent nicety: it is what keeps decision 1 true in the failure case.
Do not land 1-3 without it.

## Steps

1. `OptionForm.qml:131` (`finish`): add `root.writingPath = ""` beside the
   existing `root.path = ""`. -> verify by check 4a/4b.

2. `OptionForm.qml:98` (`writeProc`'s guard): refresh on the late path.

   ```qml
   if (!root.open || root.writingPath !== root.path) {
     // The form moved on, but the write still happened -- the adapter had
     // written the file before this answer was sent. The panel must not go
     // on showing pre-write state just because nobody is watching (#43).
     if (data && data.ok !== false && root.model) root.model.refresh()
     return
   }
   ```

   `data` is already parsed above the guard, so nothing moves. -> verify by
   check 4a.

3. `OptionForm.qml:89` (`writeProc`): add `onExited`.

   ```qml
   onExited: function (code, status) {
     if (root.model) root.model.busy = false
     if (root.open && root.writingPath === root.path && root.error === "")
       root.error = "the adapter ended without answering (exit " + code
                  + "); nothing is known to be written"
   }
   ```

   The wording keeps #28's rule: unblocking is not reporting success. ->
   verify by check 4d.

4. `OptionForm.qml:69` (`describe`): add `onExited` that clears the pending
   state and sets `root.error` when no option was received, so a form cannot
   sit open showing neither an option nor a reason. -> verify by check 4d.

5. `PkgModel.qml:216` (`_writer`): add `onExited` that sets
   `root.busy = false` and, when nothing was absorbed, sets `root.message`
   to the same "ended without answering" wording. -> verify by check 4d.

6. `PkgModel.qml`: declare `signal namingAbandoned()` beside
   `signal refreshed()` (`:74`), and cancel in `setTab` (`:198`):

   ```qml
   function setTab(i) {
     disarm()
     invalidateInspection()
     // Naming is a mode, and a mode must not outlive the tab it belongs to:
     // left behind, it swallowed every keystroke into the input name and
     // turned RETURN into a declare against a stale ref (#43). Not the ESC
     // path -- that one hands the ref back to the field on purpose.
     if (naming) { cancelNaming(); namingAbandoned() }
     tab = Math.max(0, Math.min(tabs.length - 1, i))
     cursor = 0
     if (indexTab && searching) runSearch()
   }
   ```

   -> verify by checks 4c and 4e.

7. `Menu.qml:117` (the `PkgModel` block): handle the signal where the field
   lives.

   ```qml
   PkgModel {
     id: pkg
     host: root
     onNamingAbandoned: { search.text = ""; pkg.setQuery("") }
   }
   ```

   -> verify by check 4c, and 4e for the ESC regression.

8. `PkgModel.qml`: give search its own `Process`. Add `_searcher` beside
   `_reader` (`:210`) with the same `onStreamFinished: root._absorb(text,
   false)`, and point `runSearch()` (`:306-313`) at it. `_reader` keeps
   `state` only. `_absorb` already dispatches by shape (`data.rows` vs
   `data.apps`, `:236-252`), so nothing else changes. -> verify by check 4f.

## Rollback

One commit across `OptionForm.qml`, `PkgModel.qml` and `Menu.qml`. No
adapter change, no config format, no JSON contract, no `flake.nix` change,
so `git revert` restores the previous behaviour with nothing to migrate.

If decision 1's one-liner proves insufficient -- i.e. a reviewer or a user
produces two simultaneous in-flight writes, which the `busy` audit above
says cannot happen -- the recorded fallback is a monotonic token on
`writingPath`, modelled on `_inspectToken` in the same file. That is a
larger change to step 1 only; steps 2-8 stand either way.
