# Plan: menu text follows the desktop's text size

## Approved decisions, carried over

Self-contained: everything needed to implement this is below.

**Why:** the menu multiplies the shell's font tokens by a flat `1.45`. Those
tokens already follow `[font] base-size` in `~/.config/omarchy/shell.toml`
(what `omarchy display text size` sets), so the multiplier does not make the
menu scale-aware -- it makes the menu 45% larger than the rest of the shell
at every size, and it reaches only the text this plugin draws itself, leaving
the shell's own `qs.Ui` widgets rendering at 1x inside a 1.45x surface.

**Token multipliers**, verified against the installed shell
(`omarchy-4.0.4/share/omarchy/shell/Commons/Style.qml:325-338`):
`caption` 0.833, `body` 1.0, `subtitle` 1.083, `title` 1.167,
`heading` 1.333. At `base-size` 12 that is 10, 12, 13, 14, 16.

**The mapping:**

| today | sites | becomes | at base-size 12 |
| ----- | ----- | ------- | --------------- |
| `px(Style.font.caption)` | 21 | `Style.font.title` | 15 -> 14 |
| `px(Style.font.body)` | 9 | `Style.font.heading` | 17 -> 16 |
| `px(Style.font.subtitle)` | 1 | `Style.font.heading` | 19 -> 16 |

Seven of the 31 are **geometry**, not font sizes, and take the same mapping
deliberately -- they exist to stay proportional to the text beside them:
`Menu.qml:82`, `Card.qml:25,44,157,211,312`, `OptionForm.qml:446`.

**Also decided:** the flattening of `subtitle` into `heading` is accepted
(the option path header stops being larger than the body text); the shell's
`Dropdown` needs no change because removing the multiplier resolves the
mismatch; the `OptionForm` overflow is fixed here; `Card.qml:211`'s width
arithmetic is **not** (true at every text size, pre-existing); `pointSize` is
rejected (under Wayland it is `pixelSize x 4/3` with no added DPI awareness).

**Not touched:** `Card.qml:15 maxHeight` is dead code from a separate
finding. It stays, so this diff answers one claim.

## Steps

1. `Menu.qml:35-36`: delete `readonly property real textScale: 1.45` and
   `function px(base)`. -> verify by step 7's check.

2. `Menu.qml:391` and `:469`: delete the two `textScale: root.textScale`
   hand-downs to `Card` and `OptionForm`. Leave `maxHeight:` at `:392`
   alone. -> verify by `grep -n textScale Menu.qml` returning nothing.

3. `Card.qml:16-19` and `:37`: delete the `textScale` property with its
   three-line comment, and `function px(base)`. -> verify by `grep -n`.

4. `OptionForm.qml:54-57`: delete the `textScale` property with its
   two-line comment, and `function px(base)`. -> verify by `grep -n`.

5. Retoken all 31 sites, per the table above. Mechanical:

   ```
   px(Style.font.caption)  -> Style.font.title
   px(Style.font.body)     -> Style.font.heading
   px(Style.font.subtitle) -> Style.font.heading
   root.px(...)            -> same, dropping the `root.`
   ```

   -> verify by `grep -c 'px('` returning 0 across all five files, and by
   `grep -c 'Style.font.title'` + `heading` totalling 31.

6. `OptionForm.qml:295`: wrap the `Column` in a `Flickable`. It is the
   `FocusScope`'s only top-level child, so this is contained.

   ```qml
   Flickable {
     id: body
     anchors.fill: parent
     contentWidth: width
     contentHeight: column.implicitHeight
     clip: true

     Column {
       id: column
       width: body.width
       spacing: Style.space(10)
       ...
     }
   }
   ```

   The `Column`'s `anchors { top; left; right }` become `width: body.width`
   -- a `Flickable` positions its content rather than anchoring it, and
   binding to `parent.width` would bind to the content item, whose width is
   not the `Flickable`'s. -> verify by the manual check in Tests.

7. `flake.nix`, beside `no-hardcoded-colours` (`:77-89`): add
   `no-text-multiplier`, in two parts.

   ```nix
   no-text-multiplier = pkgs.runCommand "nixarchy-pkg-text-scale" { } ''
     # Part 1, every file: no second scale, under any name.
     for f in ${./Menu.qml} ${./Panel.qml} ${./Card.qml} \
              ${./PkgModel.qml} ${./OptionForm.qml}; do
       if grep -nE 'textScale|uiScale|\bpx\(' "$f"; then
         echo "a text multiplier above; size from a Style.font.* token" >&2
         exit 1
       fi
     done
     # Part 2, the three that carried it: every font size IS a token.
     # Panel.qml is exempt from this rule only -- it sizes the badge's
     # digits from the badge's own height, a derived size with no
     # multiplier in it, and part 1 still covers it.
     for f in ${./Menu.qml} ${./Card.qml} ${./OptionForm.qml}; do
       if grep -nE 'font\.pixelSize:' "$f" |
          grep -vE 'font\.pixelSize:[[:space:]]*Style\.font\.[a-zA-Z]+[[:space:]]*$'; then
         echo "font size above is not a bare Style.font.* token" >&2
         exit 1
       fi
     done
     touch "$out"
   '';
   ```

   -> verify by `nix flake check -L` passing, and by the two negative tests
   in Tests.
