## Decisions (from the approved spec)

1. **Order:** #55, then #60, then this. The Queue tab's count is in scope.
2. **`working…` stays**, beside the motion.
3. **Busy motion runs while** `busy || inspecting || checkRunning`
   (writes, inspecting a flake, #60's check). Not while `applying`: the apply
   streams its own log.
4. **#57:** the scope line [55:117-128] becomes an `Item` that owns the
   anchors, `visible` and `height`, holding the `Text` at
   `width: parent.width`. Measured with qtdeclarative 6.12.0 offscreen: the
   current `Text { height: visible ? implicitHeight + 6 : 0; wrapMode:
   Text.Wrap }` loops, so does `bottomPadding` with
   `height: visible ? implicitHeight : 0`, and dropping the height leaves
   25 px when hidden. The wrapper does not loop and is 0 px when hidden.
5. **Hover.** `hoverEnabled: true` on the row and tab `MouseArea`s.
   - Row colour: `current ? selectedBackground : rowMouse.containsMouse ?
     hoverBackground : restBackground`.
   - `hoverBackground` = `Qt.rgba(c.r, c.g, c.b, c.a * 0.5)` with
     `c = Color.menu.selectedBackground`. Never `Qt.alpha(c, 0.5)`, which
     sets an absolute alpha.
   - `restBackground` = the same colour at alpha 0, **not** `"transparent"`
     (`#00000000`): `ColorAnimation` interpolates each channel, so fading to
     transparent passes through grey on a light theme.
   - A non-current tab under the pointer draws its label in `root.fg`
     instead of `root.dim`. The current tab is unchanged.
   - Hover never changes `cursor`, `tab` or focus.
6. **Fade.** `Behavior on color { enabled: !Style.reduceMotion;
   ColorAnimation { duration: Style.duration(120) } }` on the row and on the
   tab label. `highlightMoveDuration: 0` [55:144] stays.
7. **Busy rule.** The footer's top rule [55:389-394] becomes an `Item`,
   `clip: true`, same height:
   - the existing rule, unchanged when not waiting;
   - waiting and motion on: a segment one fifth wide in
     `Color.menu.selectedText`, `visible: root.waiting && !Style.reduceMotion`,
     `x: -width + root.busyProgress * (parent.width + width)`; a
     `NumberAnimation` runs `busyProgress` 0 → 1 in `Style.duration(1100)`,
     `loops: Animation.Infinite`, `running: root.waiting &&
     !Style.reduceMotion`. Never animate `x` itself: `from`/`to` are read
     once at start, so a card created while busy would capture width 0;
   - waiting and motion off: the rule itself in `selectedText` at opacity 1,
     no animation.
   - `waiting` = `Boolean(model && (model.busy || model.inspecting ||
     model.checkRunning))`.
8. **Tab counts** follow #60's bar badge (`Panel.qml` [60:150], [60:171]):
   - Selection (`tab 2`): `state.packages.length` whenever `state` has
     loaded, including 0; never `rows()` (a query replaces Selection's rows
     with search results, [60:121]).
   - Queue (`tab 6`): the number when `queued > 0`; `?` when `queued === -1`
     and `queueError` is set; otherwise nothing. A refresh keeps the last
     value until it answers (#60 does not clear `queued` when a read
     starts).
   - No other tab. Format `Selection 12`: one space, same colour and size.
9. **Style stub** gains `property bool reduceMotion: false` and
   `function duration(ms) { return reduceMotion ? 0 : ms }`.
   `tst_card.qml`'s `init()` sets `Style.reduceMotion = true` before every
   test (it is a singleton).
10. **One PR**, commits in step order.

### 3. Busy rule (`Card.qml`, `tst_card.qml`)

**Root properties:**

```qml
  readonly property bool waiting: Boolean(model && (model.busy
                                  || model.inspecting || model.checkRunning))
  property real busyProgress: 0
  readonly property bool busyAnimating: busyAnim.running   // for tests
  NumberAnimation on busyProgress {
    id: busyAnim
    from: 0; to: 1
    // Not Style.duration(): `running` already gates on reduceMotion, and a
    // running animation keeps the duration it started with -- if `running`
    // re-evaluated before `duration` when motion is switched back on, it
    // would start at 0 ms and spin.
    duration: 1100
    loops: Animation.Infinite
    running: root.waiting && !Style.reduceMotion
  }
```

**Footer rule** [55:389-394]. Replace the bare `Rectangle` (the one with
`opacity: 0.25` inside `Column { id: footer`; not the one at [55:353]) with:

```qml
    Item {
      objectName: "busyRule"
      width: parent.width
      height: Math.max(1, Style.space(1))
      clip: true

      Rectangle {
        objectName: "busyRuleBase"
        anchors.fill: parent
        color: root.waiting && Style.reduceMotion ? Color.menu.selectedText : root.dim
        opacity: root.waiting && Style.reduceMotion ? 1 : 0.25
      }
      Rectangle {
        objectName: "busySegment"
        width: parent.width / 5
        height: parent.height
        x: -width + root.busyProgress * (parent.width + width)
        visible: root.waiting && !Style.reduceMotion
        color: Color.menu.selectedText
      }
    }
```

`working…` [55:475] is unchanged (`root.model && root.model.busy ?
"working…" : …`).

**Fake model:** add `property bool inspecting: false` and
`property bool checkRunning: false` if not already there after the merge.

**Tests** (no timing: only `visible`, `running` and colours):
- `test_busy_rule_moves`: `Style.reduceMotion = false`; `busy = true` →
  `busySegment.visible`, and `card.busyAnimating` is true; `busy = false` → not visible, not running. The same with
  `inspecting` and with `checkRunning`.
- `test_busy_rule_without_motion`: `reduceMotion = true`, `busy = true` →
  segment not visible, not animating, the base rule's colour equals
  `Color.menu.selectedText`, and the footer still says `working…`.
- `test_busy_segment_follows_width`: with `reduceMotion = true` the
  animation is stopped, so `card.busyProgress` can be set by hand. Set it to
  0.5. At width 800 the segment's `x` is `-160 + 0.5 * 960 = 320`; set
  `win.width = 400`, and `x` is `-80 + 0.5 * 480 = 160`. `x` is a binding on
  `busyProgress` and the rule's width, so it does not depend on `visible`.
  This fails if `x` is animated with endpoints captured at start.
- `test_busy_card_created_busy`: set `busy = true` before the `Card` exists
  (a second `Card` from a `Component`, `createObject` into `win` with
  `width: 800, height: 400` -- a `Card` has no default height) with `reduceMotion = false`; after `wait(0)`, the segment's parent
  width is 800 and `busyAnimating` is true. Destroy it after.

**Traps.**
- `running` must test `Style.reduceMotion` itself: `Style.duration()` is 0
  when motion is off, and an infinite 0 ms animation spins.
- `clip: true` on the `Item`, or the segment paints outside the card at
  both ends.
- Only `busyProgress` animates. Binding `x` keeps it right across resizes.
- Each test restores `reduceMotion` via `init()`; a test that sets it false
  must not leak (it is a singleton). Only busy tests set it false, and they
  change no row or tab colour, so no `ColorAnimation` is left running into
  the next test.
