# Plan: the QML layer is checked by something other than my eyes

## Approved decisions, carried over

Self-contained: everything needed to implement this is below.

**Why:** #44 gave the QML layer a syntax gate that would have caught none of
#43's four defects, because those were logic. There are 187 adapter
assertions and zero for ~2300 lines of QML, so every UI change this month
was verified by eye on one machine -- which lost a whole verification run to
a collision, twice produced a wrong conclusion that was caught only by
looking harder, and left #42's `Flickable` unverified on `main`.

**Decisions:**

1. **Scope is `PkgModel` and `Card`** -- the two files needing almost
   nothing faked, which held four of the five defects fixed this month.
   `Menu` and `OptionForm` need five widget stubs for the remainder; their
   stale-write defect and #42's `Flickable` stay uncovered and get a
   follow-up issue.
2. **Stubs provide shape, never behaviour.** No stub runs a command, parses
   JSON or decides anything. Tests make things happen explicitly via
   `deliver(text)` and `finish(code)`. No assertion is about what a stub
   produced.
3. **It runs in CI as a `qml-tests` flake check**, headless with
   `QT_QPA_PLATFORM=offscreen`, beside `qml-syntax`.
4. **A `Flickable` is observable headless** -- probed -- but out of scope
   here.

**Everything below was measured, not assumed:**

| fact | evidence |
| ---- | -------- |
| `qmltestrunner` runs headless | passes with `QT_QPA_PLATFORM=offscreen` |
| a failing assertion gates | **exit 1** |
| a **compile error** also gates | exit 1, seen while probing |
| a stub `Process` can emit `exited(code, status)` | `Connections` receives it -- so #43's `onExited` fix is testable |
| a `Flickable` reports `contentHeight`, `clip`, `contentY` | all observable |
| **the real `Card.qml` instantiates against stubs** | `rowHeight > 0` derives through `Style.font.heading` |

**Two scaffolding traps found while probing, recorded so nobody repeats
them:**

- An absolute path in an `import` is rejected: *"is not a valid import URL
  ... Try file:/..."*. Put the subject beside the test or use a `file:` URL.
- A `qmldir` declaring only `module qs.Ui` with **no types** makes Qt report
  *"module qs.Ui is not installed"* -- which reads like a missing import
  path and is not. Every stub module needs at least one declared type.

## Steps

1. `tests/qml/imports/qs/Commons/` -- `qmldir` plus `Style`, `Color` and
   `Border` singletons, carrying only the 9 `Style.*` and 11 `Color.*`
   members these files touch and `Border.surfaceSpec`. Plain arithmetic
   (`space(v) -> round(v)`), plain colours. **Their values are asserted
   nowhere.** -> verify by step 4 loading `Card`.

2. `tests/qml/imports/qs/Ui/` -- `qmldir` plus a minimal `BorderSurface`.
   At least one type is required (see the trap above) even though `Card`
   uses none of them. -> verify by step 4.

3. `tests/qml/imports/Quickshell/Io/` -- `qmldir` plus inert `Process`,
   `StdioCollector` and `SplitParser` carrying exactly the surface
   `PkgModel` binds: `command`, `running`, `stdout`, `onStreamFinished`,
   `onRead`, and `exited(code, status)`; plus test-only `deliver(text)` and
   `finish(code)`. Nothing spawns, buffers or parses. -> verify by step 5.

4. `tests/qml/tst_card.qml` -- instantiate the real `Card.qml` with a plain
   fake model and assert the #45 arithmetic:
   - the summary width is never negative;
   - it accounts for the flags row and its gaps at N=0, N=1 and N=2, which
     until now were checked by eye and by cropping a screenshot.
   -> verify by checks 1 and 2.

5. `tests/qml/tst_pkgmodel.qml` -- instantiate the real `PkgModel.qml` and
   assert the #43 behaviours:
   - a write answer arriving after its form moved on still refreshes, and
     does not close a form reopened on the same option;
   - `setTab` cancels naming and emits `namingAbandoned`, while
     `cancelNaming` alone does not;
   - a search and a state read in flight together both land;
   - a writer that exits without answering clears `busy`;
   - `_absorb` dispatches by shape -- a `rows` answer does not overwrite the
     catalogue.

   Async assertions use `tryCompare`/`wait`, never bare `compare`, per the
   spec's flakiness risk. -> verify by checks 1 and 2.

6. `flake.nix` -- a `qml-tests` check beside `qml-syntax`:

   ```nix
   qml-tests = pkgs.runCommand "nixarchy-pkg-qml-tests"
     { nativeBuildInputs = [ pkgs.qt6.qtdeclarative ]; }
     ''
       cp ${./Card.qml} ${./PkgModel.qml} .
       cp -r ${./tests/qml}/. .
       QT_QPA_PLATFORM=offscreen QML2_IMPORT_PATH=$PWD/imports \
         qmltestrunner -input . -import "$PWD/imports"
       touch "$out"
     '';
   ```

   The subjects are copied beside the tests because of the absolute-import
   trap. -> verify by checks 1, 3 and 4.

## Tests

`nix flake check -L` locally and in CI. Nothing needs razer, a display,
`/etc/nixarchy` or the omarchy shell -- that is the point.

1. `nix flake check -L` passes with `qml-tests` included.
2. **Negative, per assertion, not committed.** For each new assertion,
   revert in a scratch copy the fix it guards and confirm **that assertion
   fails**:

   | revert | must fail |
   | ------ | --------- |
   | `writingPath` not cleared in `finish()` | the stale-write case |
   | `setTab` not cancelling naming | the naming case |
   | `_searcher` collapsed back into `_reader` | the two-reads case |
   | `onExited` removed from `_writer` | the stuck-`busy` case |
   | `Math.max(0, ...)` and the flags term removed from `Card` | the width cases |

   #41 produced an assertion that passed against the pre-fix code, and only
   trying this caught it. It is the check that decides whether this suite is
   worth having.
3. `qmltestrunner` exits **1** on those scratch copies.
4. The suite runs in the nix sandbox -- no display, no `/etc/nixarchy`, no
   shell, no razer.
5. `tests/adapter.sh` on razer still passes, unchanged.
6. CI green with the QML tests in the log rather than skipped.

## Rollback

New files under `tests/qml/` plus one `flake.nix` check. **No change to any
of the five QML files** -- the intent forbids it, so a revert cannot affect
the shipped plugin. `git revert` removes the check and the tests.

If the stubs prove to drift -- the spec's named unmitigated risk -- the
fallback is to delete the affected assertion rather than deepen the stub.
A stub that grows toward Quickshell's real semantics has become a second
implementation and is worth less than nothing.

## What this does not buy, to repeat in the PR

These assert logic, not appearance. **Nothing here would have caught #38's
text scale or #42's overflow in situ.** The QML layer is better checked
after this than before, and still not checked the way the adapter is.
