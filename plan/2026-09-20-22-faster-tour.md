# Plan: a faster tour, under a minute, that tells one story

## The approved decisions, carried

`docs/img/tour.gif` is 84 seconds, 505 frames, 2.5 MB, and its captions say
five tabs where `PkgModel.qml:28` has six: Apps, Services, Selection,
Options, Drafts, Flakes. Replace it with a tour **under 60 seconds** that
visits all six and reads as one user story.

- **Format:** `docs/img/tour.webm` (VP9) as the version the pages show,
  plus `docs/img/tour.gif` at the same path as today as fallback. Both cut
  from one take, so they cannot drift.
- **Speed:** tighter capture, not sped-up footage. No post-speed in this
  tour.
- **Story:** *I want lazygit, I don't know if it's in nixpkgs, and I don't
  want to open an editor.*
- **Machinery:** `tools/record-tour.sh`, committed. First file under
  `tools/`.
- **Untouched:** `bin/` and every `.qml`. A usability problem found while
  driving the panel becomes its own issue, as #17 did.
- **Nothing is applied.** The tour ends on queued rows.

The table lives in the script as data. Its sum is asserted under 60 before
a frame is recorded, so the limit is enforced by the tool and not by
whoever reads the output.

### The four preconditions, from the last capture's five failed attempts

Recorded as prose in `plan/2026-09-18-14-manual.md:238-249`; here each is a
check that refuses to run.

1. **The panel draws on every monitor; only the focused one takes keys.**
   Pick a monitor the terminal is not on, `hyprctl dispatch focusmonitor`
   it, record that output.
2. **`SUPER+ALT+N` is a toggle, so a tour can open by closing.** Never
   blind-toggle: `omarchy-shell shell listPlugins | jq '.[]|select(.id=="nixarchy.pkg").active'`
   is read before and after every toggle.
3. **A shell call between keystrokes raises the calling terminal.** Once
   recording starts, only `wtype` and `sleep` run.
4. **A stale index carries no `unfree` or `broken` flags**, which would
   make the tour contradict the pages around it.
   `bin/nixarchy-pkg state | jq .indexStale` must be `false`; the script
   stops rather than recording a lie. Verified false on this machine today.

Tools confirmed present here: `wl-screenrec` (there is no `wf-recorder`),
`ffmpeg`, `wtype`, `hyprctl`, `jq`. No `gifski`, so the GIF goes through
ffmpeg `palettegen`/`paletteuse`.

## Rollback

`git revert` the merge. `docs/img/tour.gif` returns to the current 84-second
take, the two pages return to embedding it, and `tools/` disappears with the
only file in it. Nothing outside `docs/` and `tools/` is touched, so there
is nothing else to restore.

The machine needs no rollback: the script restores the selection on exit and
the tour installs nothing. If it is killed uncatchably, the selection holds
the tour's toggles -- queued, never applied -- and the copies taken before
the first keystroke are left in the scratch directory to restore by hand.

## Deviations found while implementing

1. **`listPlugins`' `active` does not track whether the menu is open.** It
   reads `false` with the panel plainly on screen; it is about the plugin,
   not the surface. Precondition 2 now reads `hyprctl layers` for the
   namespace `nixarchy-pkg-menu`, which is the menu and nothing else. The
   plan inherited the wrong probe from the last capture's prose; two
   commands would have caught it there too.

2. **The menu opens on the focused monitor only, and its card is opaque.**
   `plan/2026-09-18-14-manual.md` says the panel "appears to draw on every
   monitor"; it does not. That removes the reason for precondition 1: there
   is no monitor to juggle, because the card covers whatever is behind it
   and the crop is to the card. The script records the focused output and
   crops with the card's own geometry from `Menu.qml:120-127` -- `min(1100,
   72% of the width)` by `78% of the height`, centred -- which was checked
   against a screenshot before being written down.

3. **Scene 9, the bar widget, is dropped.** The bar is at the top of the
   screen and the tour is cropped to the card, so it cannot appear in this
   video; showing it would mean either a second capture concatenated on, or
   a crop wide enough to put the whole desktop in the tour. Neither is worth
   four seconds when `docs/img/11-bar-widget.png` already shows the widget
   in the manual. Eight scenes, 52 seconds, eight under the limit.

4. **One shell call does run during the recording: the toggle that opens the
   panel.** Precondition 3 said only `wtype` and `sleep` would. Keeping to
   that would mean opening the panel before the recorder starts, and the
   story opens on the keybind. What actually raised the terminal last time
   was *this session's tool calls*, not an IPC call from a script that owns
   the run -- measured: a toggle left focus where it was. The stronger rule
   the measurement did find is that the whole run must be **one detached
   invocation**: a `focusmonitor` issued from this session was undone
   immediately by the next tool call raising the terminal.

5. **`wtype` cannot drive this panel, and poisons it for everything else.**
   It attaches a virtual keyboard carrying its own keymap, after which the
   client resolves only raw navigation scancodes: arrows keep working while
   letters, `/`, `space`, `Return` and `Tab` go silently dead, and the damage
   outlives the run. Diagnosis took several takes because the panel looks
   fine and answers arrows. Everything is sent with `ydotool` now, and
   because the same deafness creeps back after enough driving, every take
   starts with `omarchy-restart-shell`.

6. **`ydotool key N:1 N:0` drops keys.** Press and release sent as one batch
   share a timestamp and the client discards them at random -- a `Right`
   that never changes tab, a `Return` that never queues. Held for 50ms as
   two events, nothing is lost. This was behind most of what looked like
   unrelated flakiness.

7. **`ydotool type -- text` types the `--`.** There is no end-of-options
   marker; the scenes that typed nothing were typing `--` at a list that
   ignored it.

8. **`hyprctl dispatch workspace 13` is a Lua syntax error on Hyprland
   0.56**, not a workspace switch, and it exits 7 rather than saying so. The
   form is `hl.dsp.focus({ workspace = "13" })`, found by reading how
   `omarchy-restart-shell` and `workspace-groups.lua` write theirs. The
   legacy form is kept as a fallback.

9. **The tour's order is dictated by two one-way doors, not by the story.**
   Flakes keeps the keyboard in its field whatever is pressed, so nothing
   can leave it: it has to be last. The option form is the same -- once
   opened, Escape closes it and every further Escape is still eaten by
   `clearInspection()` (three in a row leave the query sitting in the
   field), so the tab cannot be left either. The Options scene therefore
   searches and shows the 25k options, and stops short of pressing Return.
   The form itself is already in the manual as `docs/img/08` and `09`.
   Options also lists nothing at all until something is searched, so
   opening a form from the unsearched list -- tried first -- shows an empty
   tab and then closes the menu.

10. **The search is debounced (`Menu.qml:265`), so Return too soon queues
    nothing.** It finds no row and fails silently, which reads on the
    recording as a package searched for and never added. The scene waits
    2.5s between the query and the Return.

11. **The GIF is 8fps and 64 colours**, which is how it comes in at
    2 264 595 bytes against the 2 553 559 it replaces. At 10fps it was
    2.6 MB and at 12fps 3.2 MB: the frame rate dropped before the tour lost
    a scene, as the plan said it should. The webm is 456 757 bytes.

12. **A third stale claim, and the gap behind all of them.**
    `docs/manual/the-menu.md:7` also said "five tabs", and its tab table
    listed five: **Flakes was missing from the manual entirely**. That is
    what "five tabs" had been counting. The row is added here.

13. **The bar-widget scene stays dropped** (deviation 3), so the tour is
    eight scenes and 52s of budget; the encoded take is 56.8s, including
    the panel opening.

## A finding for its own issue

`nixarchy-pkg pending` reports `count: 1` after a service toggle **and** a
package add, and lists only the package. Two queued changes, a count of one
-- which is the number the tour's own footer shows. Not fixed here: this task
records a tour, and `plan/` forbids touching `bin/` during it, the same rule
that sent #17 to its own issue.
