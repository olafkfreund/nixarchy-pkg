# Plan: a faster tour, under a minute, that tells one story

## The approved decisions, carried

`docs/img/tour.gif` is 84 seconds, 505 frames, 2.5 MB, and its captions say
five tabs where `PkgModel.qml:28` has six: Apps, Services, Selection,
Options, Drafts, Flakes. Replace it with a tour **under 60 seconds** that
visits all six and reads as one user story.

- **Format:** `docs/img/tour.webm` (VP9) as the version the pages show,
  plus `docs/img/tour.gif` at the same path as today as fallback. Both cut
  from one take, so they cannot drift.
- **Speed:** tighter capture, not sped-up footage. No post-speed in this
  tour.
- **Story:** *I want lazygit, I don't know if it's in nixpkgs, and I don't
  want to open an editor.*
- **Machinery:** `tools/record-tour.sh`, committed. First file under
  `tools/`.
- **Untouched:** `bin/` and every `.qml`. A usability problem found while
  driving the panel becomes its own issue, as #17 did.
- **Nothing is applied.** The tour ends on queued rows.

### The scene table, with its keystrokes

Budget totals 56s, leaving 4s under the limit. `TAB` moves one tab right;
the tab order is the `PkgModel.qml:28` order.

| # | Scene | Keys | Budget |
|---|-------|------|--------|
| 1 | Panel opens on **Apps** | (open; see step 3) | 4s |
| 2 | **Services**, toggle one on | `TAB`, `Down`x3, `SPACE` | 5s |
| 3 | **Selection**, the toggle already waiting | `TAB` | 5s |
| 4 | **Options**, search `openssh`, open the form | `TAB`, `/`, `openssh`, `Down`, `RETURN` | 9s |
| 5 | **Drafts**, the option waiting | `ESC`, `TAB` | 5s |
| 6 | **Flakes**, a flakeref, its packages | `TAB`, `github:nix-community/nixvim`, `RETURN` | 8s |
| 7 | **Apps**, `/lazygit`, exact match first, queue it | `TAB`, `/`, `lazygit`, `SPACE` | 10s |
| 8 | **Selection**, three queued, none built | `TAB`x2 | 6s |
| 9 | The bar widget, same count | close panel | 4s |

Scene 7 lands at 41s on purpose: queue-then-apply only reads once the
reader knows what a queue is. Moving it to the front is a row swap in the
table, not a rewrite.

The table lives in the script as data. Its sum is asserted under 60 before
a frame is recorded, so the limit is enforced by the tool and not by
whoever reads the output.

### The four preconditions, from the last capture's five failed attempts

Recorded as prose in `plan/2026-09-18-14-manual.md:238-249`; here each is a
check that refuses to run.

1. **The panel draws on every monitor; only the focused one takes keys.**
   Pick a monitor the terminal is not on, `hyprctl dispatch focusmonitor`
   it, record that output.
2. **`SUPER+ALT+N` is a toggle, so a tour can open by closing.** Never
   blind-toggle: `omarchy-shell shell listPlugins | jq '.[]|select(.id=="nixarchy.pkg").active'`
   is read before and after every toggle.
3. **A shell call between keystrokes raises the calling terminal.** Once
   recording starts, only `wtype` and `sleep` run.
4. **A stale index carries no `unfree` or `broken` flags**, which would
   make the tour contradict the pages around it.
   `bin/nixarchy-pkg state | jq .indexStale` must be `false`; the script
   stops rather than recording a lie. Verified false on this machine today.

Tools confirmed present here: `wl-screenrec` (there is no `wf-recorder`),
`ffmpeg`, `wtype`, `hyprctl`, `jq`. No `gifski`, so the GIF goes through
ffmpeg `palettegen`/`paletteuse`.

## Steps

1. `tools/record-tour.sh`: the scene table as data, and the budget assertion
   over it → verify by running the script with a `--check` flag that runs
   the preconditions and the budget sum and exits before recording; expect
   it to print the total as 56 and exit 0.
2. `tools/record-tour.sh`: the four preconditions, each with its own refusal
   message → verify by running `--check` with the panel deliberately left
   open; expect a non-zero exit naming the panel state, not a recording.
3. `tools/record-tour.sh`: selection backup, the `trap` that restores
   `~/.config/nixarchy/apps.nix` and `services.nix`, and the refusal to
   start when `bin/nixarchy-pkg pending` reports a non-zero count → verify
   by `sha256sum` of both files before and after a `--check` run; expect
   identical. `pending.count` is 0 on this machine today.
4. `tools/record-tour.sh`: the capture itself -- focus the chosen monitor,
   open the panel, `wl-screenrec` the output region, drive the scenes with
   `wtype` and `sleep`, stop → verify by the source file existing and
   `ffprobe` reporting a duration within a second of 56.
5. `tools/record-tour.sh`: encode both artifacts from the one take, VP9 webm
   and a 12fps width-620 GIF via palettegen → verify by `ffprobe` on each
   and `ls -l` on the GIF.
6. Run it, and read the result: extract one frame per scene and look at them
   → verify that six distinct tab names appear, `lazygit` is the first
   result of its search, and the closing Selection shows queued rows with
   nothing built. A take that fails this is discarded, not published.
7. `docs/index.md:13`: replace the image with a `<video>` carrying the GIF
   as fallback, and drop "five tabs" from the caption → verify by reading
   the rendered line and by `grep -c 'five tabs' docs/` being 0.
8. `docs/manual/getting-started.md:69,71`: the same embed change, and the
   heading "The whole loop, in a minute and a half" becomes a claim that
   matches the new length → verify by grep; the phrase "minute and a half"
   must not survive.
9. Commit the new artifacts, delete nothing else, open the PR linking all
   three files.

Steps 4 and 6 need this desktop: Hyprland running, the shell up, the plugin
enabled. CI cannot cut this recording, which is why steps 1-3 put the
checks in the script.

## Rollback

`git revert` the merge. `docs/img/tour.gif` returns to the current 84-second
take, the two pages return to embedding it, and `tools/` disappears with the
only file in it. Nothing outside `docs/` and `tools/` is touched, so there
is nothing else to restore.

The machine needs no rollback: the script restores the selection on exit and
the tour installs nothing. If it is killed uncatchably, the selection holds
the tour's toggles -- queued, never applied -- and the copies taken before
the first keystroke are left in the scratch directory to restore by hand.
