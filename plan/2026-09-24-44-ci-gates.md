# Plan: CI checks the things that actually break

## Approved decisions, carried over

Self-contained: everything needed to implement this is below.

**Why:** CI parses no QML and runs no adapter test. ~2300 lines of QML have
no static check at all, and the 1332-line script that performs every write
to a user's NixOS config is protected only by somebody remembering to run
`tests/adapter.sh` on razer.

1. **A `qml-syntax` flake check**, gating on `qmllint`'s exit code.
   Measured: **255** on a syntax error, **0** on a clean file, and the 780
   import warnings these files produce do **not** affect exit status.
   `qmllint` and the Qt QML module dir are in the same store output.
   Pass `-I` so a failed run is readable; it does not change the gate.
   **Do not fail on warnings** -- they are unresolvable host imports.
2. **No committed catalogue fixtures.** `fresh_config()` builds from this
   machine's own catalogue on purpose; frozen copies would assert against a
   catalogue nobody ships and hide drift.
3. **Split `tests/adapter.sh` instead**, so the machine-independent sections
   run everywhere with every existing assertion unchanged.
4. **`draft` and `reindex` get stub-driven tests.**
5. **aarch64 is deferred by the approver** -- not dropped, not fixed. The
   `flake.nix:8` declaration and the `nix flake check` warning both stay.

## Steps

1. `flake.nix`, beside `no-text-multiplier`: add the `qml-syntax` check.

   ```nix
   # ~2300 lines of QML and nothing parsed them: a syntax error shipped and
   # failed at runtime in the shell, where the symptom is a plugin that
   # silently never draws (#44). qmllint exits 255 on a syntax error and 0
   # on a clean file; its import warnings do not affect that, and must not
   # become a gate -- qs.Commons and qs.Ui belong to the host shell and
   # cannot resolve here by design. -I is for whoever reads a failure: two
   # unresolvable host modules is a known condition, three including
   # QtQuick looks like a broken check.
   qml-syntax = pkgs.runCommand "nixarchy-pkg-qml-syntax"
     { nativeBuildInputs = [ pkgs.qt6.qtdeclarative ]; }
     ''
       for f in ${./Menu.qml} ${./Panel.qml} ${./Card.qml} \
                ${./PkgModel.qml} ${./OptionForm.qml}; do
         qmllint -I "${pkgs.qt6.qtdeclarative}/lib/qt-6/qml" "$f" || exit 1
       done
       touch "$out"
     '';
   ```

   -> verify by `nix flake check -L` passing, and by test 2 below.

2. `tests/adapter.sh:40`: the hard guard becomes a flag.

   ```bash
   # The catalogue sections build from this machine's own templates, so they
   # only run on a nixarchy box. The rest -- flake, search, apply, and the
   # source-shape checks -- build their own fixtures or stub the writer, so
   # they run anywhere, including CI, where they are the only protection the
   # adapter has on a pull request (#44).
   HAVE_CATALOGUE=true
   [ -d "$TEMPLATES" ] || { HAVE_CATALOGUE=false
     echo "note: $TEMPLATES not present; catalogue sections will be skipped"; }
   ```

   -> verify by test 4.

3. Wrap each catalogue-dependent range from the table in
   `if $HAVE_CATALOGUE; then` / `else echo "  skip: needs $TEMPLATES"; fi`.

   **Do not re-indent the bodies.** Bash does not care, and leaving them
   alone keeps the diff to the guard lines, so a reviewer sees what changed
   rather than a 350-line reformat. Note it in a comment so the next reader
   knows it is deliberate. -> verify by tests 3 and 4.

4. Split the `a write keeps the file it wrote to` section at line 553 so its
   flake half stays outside the guard. Those cases assert #39's mode and
   symlink guarantees and need no catalogue. -> verify by test 4 showing
   them run without `/etc/nixarchy`.

5. `tests/adapter.sh`: a new machine-independent section covering `draft`
   and `reindex`, following the PATH-stub pattern the `apply` section
   already uses (`:429`):

   - `draft new` / `draft undraft` forward their arguments to
     `nixarchy-pkg-new` / `nixarchy-pkg-undraft`, asserted by a stub that
     records `argv`.
   - a failing writer surfaces as `{"ok": false}` carrying its message.
   - `draft` and `pkg` reject an unknown action with a usage error.
   - `reindex` with a stub `nixarchy-search` that does nothing answers
     `ok: false` and reports the index still stale. Worth pinning: a review
     of #39 called this behaviour a defect, and it is correct.

   -> verify by test 5.

6. `.github/workflows/ci.yml`: add `- run: bash tests/adapter.sh` after the
   `nix flake check` step. -> verify by test 6.

## Tests

`nix flake check -L` locally; the suite on **razer** over ssh, never p620.
No text-size sweep anywhere -- nothing here needs one.

1. `nix flake check -L` passes with `qml-syntax` included.
2. **Negative, not committed:** on a scratch copy with `Item { {{{` planted
   in `Card.qml`, `qml-syntax` **fails**; on the tree as it stands it
   passes.
3. `bash tests/adapter.sh` on **razer**: every section runs, all pass, and
   the number of `ok` lines is **not lower** than before the split. Count
   before and after and compare -- this is the check that the guard did not
   silently swallow a section.
4. `bash tests/adapter.sh` with `TEMPLATES` pointed at a directory that does
   not exist: the catalogue sections announce they are skipped, the `flake`,
   `search`, `apply`, flake-half, source-shape and `failure is a value`
   sections run and pass, and the exit status is **0**.
5. The new `draft`/`reindex` cases **fail** when their stub is made to fail,
   proving they are assertions and not smoke.
6. CI is green on the pull request and its log shows the adapter suite
   running rather than skipping.

## Rollback

`flake.nix`, `tests/adapter.sh` and `ci.yml` only. No adapter logic, no QML,
no config format, no JSON contract. `git revert` restores the previous CI
with nothing to migrate.

If `qml-syntax` proves noisy across a nixpkgs bump -- a future `qmllint`
tightening and failing on something that is not a syntax error -- the
fallback is to pin the checker rather than delete the check.

## Honest limitation, to repeat in the PR

`qml-syntax` would have caught **none** of #43's four defects. Those were
logic. It catches the class that silently ships a plugin that never draws.
The QML layer still has no behavioural tests, and this task does not give it
any.
