# Plan: a real manual, on a Pages site in nixarchy's style

## The approved decisions, in full

**Schedule.** Write against #11 and #4 merged. PR #12 and PR #13 are both
`MERGEABLE / CLEAN`. `manual/flakes.md` ships inside #3's own PR, where
the feature and its page land together; the sidebar check below fails
loudly if it is forgotten. Not against `main`, which names a tab #11
removes; not blocked on #3, which is unpushed and conflicts with #11.

**The site.** `docs/`, arranged as nixarchy's is: no theme gem, so what
builds on Pages is what is in the directory. `style.css` and `manual.js`
are copied, not referenced -- sharing them across repositories needs a
build step, which the intent forbids -- and each carries a comment naming
where it came from, so the fork is known rather than discovered.

**Thirteen pages**, each titled as something a person does:
`index`, `getting-started`, `the-menu`, `the-bar`, `apps-and-services`,
`packages`, `options`, `drafts`, `flakes` (with #3), `applying`,
`from-a-terminal`, `how-it-works`, `troubleshooting`.

**The adapter CLI gets a page**, settled at gate 1, and with it the cost:
its output becomes an interface. The page says which fields are stable
and which are the panel's business.

**Screenshots are re-captured**, not reused: the eleven in
`assets/showcase/` predate #11 and four show a tab named `Packages`.

**CI does three things**: reachability, a Jekyll build so a broken Liquid
tag fails the PR, and deploy on `main`.

**Not a second key table.** `?` is generated from `bin/nixarchy-pkg-keys`
and is on screen when the question is asked. The manual says what a key
is *for*.

## Steps

### The scaffold

1. **Branch from the merged tree.** Merge PR #12, then PR #13, then
   branch `docs/14-manual` from `main`. The existing `docs/14-manual`
   branch carries only the artifacts and is rebased onto that.
   -> verify by `git log --oneline` showing both merges, and
   `grep '"Selection"' PkgModel.qml` finding the renamed tab.

2. **`docs/_config.yml`** -- `title: nixarchy.pkg`, description, `url`
   and `baseurl: /nixarchy-pkg`, `include: [manual]`, and the `nav:` list
   in reading order. A comment says the order is stated rather than
   derived, and why -- alphabetical opens the manual on "Applying".
   -> verify by the reachability check in step 11.

3. **`docs/_includes/logo.html`** -- the wordmark, generated once:

       curl -sfL -o /tmp/dcp1.flf \
         'https://raw.githubusercontent.com/xero/figlet-fonts/master/Delta%20Corps%20Priest%201.flf'
       figlet -w 400 -f /tmp/dcp1.flf PKG

   `PKG`, not `NIXARCHY.PKG`: measured at **38 columns by 9 rows**
   against 131 columns for the full name, which is too wide for a
   masthead and unreadable at a phone's floor. The same typeface as
   nixarchy's so the two read as relatives; this project's own word so
   nixarchy's name is not on a different project's manual. The comment
   records the command and the column count, as nixarchy's does, because
   the CSS is tuned to it.
   -> verify by the rendered art being 9 lines and 38 columns wide.

4. **`docs/assets/style.css`** -- copied from nixarchy's, with a
   provenance comment at the top, and **one retuning**: the `.logo`
   `font-size: clamp(...)` is sized for 92 columns there and this
   wordmark is 38. Start from `clamp(0.6rem, 2.4vw, 1.6rem)` -- the same
   apparent width, scaled by 92/38 -- and check it by eye at phone and
   desktop widths. The `letter-spacing: -0.0425em` and
   `line-height: 1.09375` are **kept exactly**: nixarchy's comment
   records them as measured values that stop the block glyphs rendering
   with hairline seams, and they are a property of the font, not of the
   word.
   -> verify by the masthead having no seams and not overflowing at
   375px.

5. **`docs/assets/manual.js`** -- copied, with the same provenance
   comment. The sidebar filter, `/` to focus, `Escape` to clear.
   -> verify by step 13.

6. **`docs/_layouts/{home,manual}.html`** -- copied, with the title,
   tagline and the offsite links changed: `Source` to this repository,
   and a link to nixarchy's manual rather than Omarchy's.
   -> verify by the build in step 12.

## Deviations found while capturing

1. **A screen recording was added, and was not in the approved plan.** The
   approver asked for one while step 14 was being executed. `docs/img/tour.gif`
   is 84 seconds of the real panel: the five tabs, a search of nixpkgs, and one
   package queued and not installed. Weighted to match nixarchy's own demo gif
   -- 2.5 MB against their 2.7 MB -- rather than to whatever ffmpeg produced
   first, which was 5.5 MB.

2. **The index had to be rebuilt before capturing.** The panel was reporting
   *index stale*, and a stale index carries no `unfree` or `broken` flags at
   all. The flags screenshot would therefore have shown a package with no
   flags while its caption claimed the flags were shown -- a picture that
   contradicts its own page. After `reindex`: 113,416 packages, 25,568
   options, and 2,716 unfree-flagged packages where there had been none.

3. **One screenshot was captured wrong and had to be retaken.** `06` showed
   `/ripgrep` in the search box and a single unrelated result, because the
   field already had focus and the `/` typed as a character instead of
   focusing it. Caught by reading the saved PNG rather than by trusting the
   capture; the retake shows the exact-match-first ranking the page claims.

4. **The capture fought the desktop, and the cause is worth recording.**
   Five attempts failed for reasons that were not obvious: the workspace kept
   flipping back because *this session's own terminal* is on the same desktop
   and every tool call raises it; `SUPER+ALT+N` is a toggle, so beginning a
   tour with it closed a panel that was already open; and the panel appears to
   draw on every monitor while only the focused one takes keys, so keystrokes
   were landing on an instance that was not being recorded. The working
   recipe: put the panel on a monitor the terminal is not on, or make no shell
   calls between keystrokes, and verify open/closed state before toggling.

## A finding for its own issue

While driving the panel: `Menu.qml`'s search field hands back only `Down`,
`Up`, `Return`, `Enter` and `Escape`. `Left`, `Right`, `TAB` and the letter
keys are not handed back -- they move the text caret or type. So **once a
search is typed, the tab cannot be changed without closing the menu**:
`ESCAPE` clears the text but leaves focus in the field. This is the same
class of problem #3's branch fixes for the Flakes tab. Not fixed here: this
task documents what exists, and a fix during a documentation pass is how a
manual ends up describing a thing nobody reviewed.

## Rollback

`git revert` the merge. `docs/` is additive and nothing outside it
changes except `README.md`, so reverting restores the previous README and
removes the site's source. The published site stops updating at the last
successful deploy and is removed by disabling Pages in settings -- which,
like enabling it, is not something this repository can do.

No machine state is touched. The screenshot capture edits nothing: its
proof is the checksum, and if a checksum differs the capture is wrong and
the shots are discarded rather than published.
