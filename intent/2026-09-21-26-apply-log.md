# Intent: the apply log is blank until the build ends, then shows raw ANSI

## Problem

Pressing `a` starts a rebuild that takes minutes, and for all of those
minutes the card shows nothing: no log lines, no tabs, no footer. Driven on
razer, the pane stayed empty through the whole `nix build`. The only sign
that anything was happening was the polkit prompt appearing when nh reached
the switch.

When the build ends, the whole log arrives at once, and nh's colour escapes
are drawn as text:

    ␛[1mADDED␛[0m
    [␛[1;32mA␛[0m␛[1m+␛[0m] ␛[1mhello   ␛[0m␛[32m2␛[0m.␛[32m12␛[0m...
    ␛[32m>␛[0m Activating configuration

The part a person most wants to read, the ADDED/CHANGED summary of what the
rebuild did, is the part the escapes corrupt.

There are two separate causes:

- `cmd_apply` (`bin/nixarchy-pkg:1118`) runs `nixarchy-apply` inside
  `out=$(...)` and prints `$out` only after it exits. Nothing reaches the
  panel's line reader (`PkgModel.qml`, `_apply`'s `SplitParser`) until the
  end. The comments on both sides say the log is streamed, and the reader
  was written for a stream.
- Nothing removes terminal control sequences. `Menu.qml:329` draws the log
  as `Text.PlainText`, which is right for external text, and it shows the
  escapes literally.

## Proposed outcome

- Log lines appear in the card as the build prints them. A person watching
  can see the build moving, and can see where it stopped if it fails.
- The log reads as plain text: no escape sequences, no stray `[1m`.
- The contract stays the same: the last line is the single JSON object
  the panel parses, and `ok` still tells a switch from a decline
  (the "Not switching." check must still see the whole output).
- `ESC` while applying still stops watching without stopping the build.

## Affected users and systems

- Everyone who applies from the panel, on every host.
- `bin/nixarchy-pkg` `cmd_apply`, and `tests/adapter.sh`'s apply cases.
- Possibly `PkgModel.qml`'s `_apply` reader, if stripping happens there
  instead.
- Not `nixarchy-apply` or nh: they are right to colour a terminal.

## Constraints

- Must keep the last-line JSON contract, and must keep the decline
  detection working on the full output. Streaming must not turn "Not
  switching." into "applied".
- Must not hide a failure: nix's error lines still arrive, uncoloured.
- Must stay plain text in the QML. The fix is removing escapes, not
  rendering them as rich text, because the log is external input.
- `set -euo pipefail` is on. A streaming pipeline must not let a pipe
  status mask `nixarchy-apply`'s own exit code, which is how #24 happened.

## Open questions

1. **Strip where?** In the adapter, where one `sed` covers the panel and a
   terminal user alike, or in the QML reader. The recommendation is the
   adapter, because the adapter's output is the contract.
2. **Ask for no colour instead of stripping it?** `NO_COLOR=1` or nh's own
   flag might stop the escapes at the source. That's cleaner if every tool
   in the chain honours it. The spec should measure it rather than assume,
   and strip anyway as a fallback.
3. **Should the card say "building…" before the first line arrives?**
   Evaluation can be silent for tens of seconds even when streaming works.
