# Spec: say how old the search index is and what changed, and why a reindex failed

## Design

**Decisions from intent approval** (its open questions, taken as
recommended):

1. No automatic reindexing in this repo. The panel only says how old the
   index is. A reindex-on-new-generation unit is proposed to nixarchy
   (companion issue B).
2. What changed is named in plain words (nixpkgs, options, app list,
   flatpaks…), never as version numbers.
3. When a reindex leaves the index stale, show the lines `nixarchy-search`
   printed to stderr in that run, without its progress lines and the
   picker's no-terminal noise, and point to `index-errors.log`. The log is
   not parsed.
4. A reindex-only mode is asked of nixarchy (companion issue A). The stamp
   check stays here either way.

**Decisions for the owner** (choices this spec makes; overturn them here):

- **No old/new nixpkgs revision.** Question 2 asked whether to show one
  "when the path carries one". It does not: the stamp's nixpkgs line is
  `/nix/store/<hash>-<hash>-source` (measured on p620), with no revision in
  it. Getting one would mean evaluating Nix, which `state` must not do.
  So the answer is only "nixpkgs changed".
- **A failed reindex answers with `error`, not only `message`.** Today it
  answers `ok: false` with no `error` (`bin/nixarchy-pkg:1462-1465`), which
  breaks the documented contract: "`ok` on every object, and `error` when
  `ok` is false" (`docs/manual/from-a-terminal.md`, "What is stable"). The
  panel then shows `error` in its footer, as for any other failed command
  (`PkgModel.qml:265`, the `ok === false && error` branch).
- **A new `index` object, beside `indexStale`.** `indexStale` keeps its
  meaning and type. The new object carries the rest, so a terminal user
  gets the same facts as the panel.
- **The stamp's format is recognised by the store-path suffix of each of
  its seven lines**, not by line count alone. An unrecognised stamp gives
  `changed: null` and the plain "stale" wording. A format version written
  by nixarchy would be cleaner, but would not cover stamps already on disk.
- **`indexStale`'s corner cases are kept, not fixed.** For example, an
  index with no stamp on a machine with no `nixarchy-search` reads fresh
  today, and still will. Changing that is a contract change for another
  issue.

### Measured (p620, 2026-11-16, throwaway `XDG_CACHE_HOME`)

- `nixarchy-search --reindex </dev/null`: 44.5 s wall, 5.0 GB peak RSS,
  **exit 0**. Its stderr is exactly three lines: "Building the search index.
  This happens when nixpkgs changes.", "  indexing nixpkgs (this takes about
  a minute)...", and fzf's "inappropriate ioctl for device".
- The resulting `index-errors.log` has 600 lines; 598 are
  `evaluation warning:` lines. That is why it is not shown or parsed.
- `nixarchy-pkg state` takes 0.11-0.12 s today. The seven `searched`
  lookups that `index_stale` already makes take 0.03 s of that.
- The live cache on p620: `index.tsv` 59.8 MB and `stamp` 501 bytes, both
  written 2026-11-02; six of the seven stamp lines differ from now.

### 1. Adapter: one function for the index facts

Line numbers are main's. On `feat/60-truthful-queue` the same functions
sit at `index_stale` :282, `cmd_search` :399, `cmd_reindex` :1896 and
`cmd_state` :1911, with the same bodies.

`index_stale` (`bin/nixarchy-pkg:257-265`) is replaced by `index_facts`,
which prints one JSON object and is computed once per command:

```json
{ "status": "fresh" | "stale" | "missing",
  "builtAt": 1793659612,
  "changed": ["nixpkgs", "options", "app list", "flatpaks", "new-package row"] }
```

- `status`: `missing` when `index.tsv` is absent or empty (`[ -s ]`).
  Otherwise `fresh` when `$(cat "$STAMP" 2>/dev/null)` equals the key
  string built exactly as `index_stale` builds it today, else `stale`. The
  comparison is kept byte for byte, including its corner cases (for
  example a missing stamp *and* no `nixarchy-search` on `PATH` compare
  equal and read `fresh`, as they do today), so `indexStale` cannot change
  meaning.
- `builtAt`: the index file's modification time in Unix seconds
  (`stat -c %Y`), only when `status` is not `missing` and `stat` succeeds;
  otherwise `null`. It is when the index was built, not when it went
  stale; the panel says "built … ago", never "stale for".
- `changed`: a list only when all of these hold, otherwise `null`:
  - `status` is `stale`;
  - `nixarchy-search` is on `PATH` (else `searched` answers empty strings,
    which would read as "everything changed");
  - the stamp exists and, read with `mapfile -t` (which keeps an empty
    line: `optionsjson` is legitimately empty on a system without the
    NixOS manual, `nixarchy-search` lines 56-58), has exactly seven lines;
  - **the format is recognised**: every stamp line and every current value
    ends the way its input's store path does, or is empty where empty is
    allowed:

  | Line | Input | Must end with | Name |
  | --- | --- | --- | --- |
  | 1 | `nixpkgs` | `-source` | nixpkgs |
  | 2 | `walk` | `-pkg-index.nix` | index builder |
  | 3 | `optionsjson` | `/options.json`, or empty | options |
  | 4 | `appindex` | `-nixarchy-app-index.tsv` | app list |
  | 5 | `apptable` | `-nixarchy-app-attrs.tsv` | app list |
  | 6 | `flatpakrows` | `-nixarchy-flatpak-rows.tsv` | flatpaks |
  | 7 | `pkgnewrow` | `-nixarchy-pkg-new-row.tsv` | new-package row |

  (All seven match on p620's stamp and current values.) A reordered or
  replaced input fails the suffix check, so a new seven-line format gives
  `null`, not wrong names. Then each line that differs contributes its
  name, in input order, without duplicates.

  A stale index with an empty list cannot happen once the strings differ
  and is treated as `null` too.

`index_facts` uses `stat`, `cat` and the existing `searched`; no Nix, and it
never reads `index.tsv`'s content. `indexStale` everywhere becomes
`status != "fresh"`, so its value is unchanged in every case.

Answers that change:

- `state` (`:1469`) and `search` (`:374`): add `index`. `search` still dies
  first when there is no index (`:394`), with "no search index yet -- run:
  nixarchy-pkg reindex": that error is the missing fact, and `state` carries
  the full object.
- `reindex` (`:1454-1466`):

  ```bash
  err=$(NIXARCHY_IN_PICKER=1 nixarchy-search --reindex </dev/null 2>&1 >/dev/null) || :
  ```

  (stderr captured, stdout dropped; shellcheck 0.11 is clean on this line,
  checked.)

  Then `index_facts`. When `status` is `fresh`:
  `{ok: true, indexStale: false, index, message: "index rebuilt"}`.
  Otherwise `{ok: false, indexStale: true, index, error, detail}` where:
  - `detail` is an array of strings: `err`'s lines, trimmed, minus known
    noise, at most the last 8. Noise is: the two progress lines above; the
    two "no option index: documentation.nixos.enable is off …" lines
    (`nixarchy-search` lines 79-80); `inappropriate ioctl for device`; and
    any `evaluation warning:` line (the `tail -5` that `nixarchy-search`
    prints on failure can be all warnings, for example when the evaluator
    is killed for memory and writes nothing).
  - `error` is one line: `"the search index is still <stale|missing>: "`
    then the last line of `detail` that is not the
    "indexing nixpkgs failed; the end of …" header; or, when there is none,
    `"nixarchy-search gave no reason"`. It always ends
    `" -- see <cache>/index-errors.log"`. That log is from the last run
    that reached indexing, which may not be this one; the manual says so.

  The captured stderr is held in a variable, never written to a file.

### 2. Panel

- `PkgModel.qml`: new `property var index: null`. `_absorb` (main :255-300)
  takes `indexStale` and `index` from **any** answer that carries them, at
  its top, before it branches. Today a failed reindex with `error` returns
  early at the `ok === false && error` branch (main :265-268) and a
  successful one falls into the non-state branch; both would otherwise
  drop the new facts. If #64 lands first, its own `indexStale` line in the
  non-state branch is replaced by this one. New
  function `indexLine(now)` returns the text the card shows, so it can be
  tested with a fixed `now`:
  - `missing`: "no search index — r to build it"
  - `stale` with `builtAt`: "index built 14 days ago — nixpkgs and 4 more
    changed — r to rebuild". One name is said alone, two as "a and b",
    more as "first and N more". The age is minutes under an hour, hours
    under two days, days after that.
  - `stale` with `changed: null`: "index built 14 days ago — r to rebuild".
  - `stale` with `builtAt: null`: "index stale — r to rebuild" (plus the
    changed names if known).
  - `builtAt` is seconds and `now` is milliseconds (`Date.now()`); the age
    is `max(0, now/1000 - builtAt)`. Under a minute reads "just now"; one
    unit is singular ("1 day").
  - no `index` (an adapter older than this change): today's "index stale —
    r to rebuild".
- `Card.qml` (`:356-357` on main, `:370-371` on #60): `text:
  root.model.indexLine(Date.now())`, still shown only when `indexStale`.
- A failed reindex already reaches the footer through `error`. Nothing else
  changes in the panel.

### 4. Tests

`tests/adapter.sh`, in its existing no-catalogue "draft and reindex"
section (`:664-723`), with a stub `nixarchy-search` on `PATH` whose
variables point at files in a temp dir (the adapter's `searched` reads
`nixpkgs=…` lines from the script, so the stub just defines them):

- No index, and a 0-byte index: `state` says `status == "missing"` and
  `builtAt == null`.
- An index and no stamp: `stale`, `changed == null`, `builtAt` a number.
- No `nixarchy-search` on `PATH` with a stale stamp: `changed == null`.
- A seven-line stamp whose line 2 ends `-other.nix`: `changed == null`.
- A seven-line stamp with an empty line 3 that matches: `fresh`.
- An index and a matching seven-line stamp: `fresh`, `changed == null`.
- Change lines 1 and 4: `stale`, `changed == ["nixpkgs", "app list"]`.
- Change lines 4 and 5: `changed == ["app list"]` (no duplicate).
- A six-line stamp: `stale`, `changed == null`.
- `indexStale` agrees with `status` in all of these.
- The existing no-op reindex stub: `ok == false`, `error` present and
  containing `index-errors.log`.
- A stub that prints the three noise lines and builds nothing: `detail`
  is empty and `error` says nixarchy-search said nothing.
- A stub that prints "indexing nixpkgs failed; …" and `boom`, exit 1:
  `error` contains `boom` and names the log.
- A stub that prints the failure header and five `evaluation warning:`
  lines: `detail` holds only the header line, and `error` says
  "nixarchy-search gave no reason".

`tests/qml/tst_pkgmodel.qml`: `indexLine` for missing, stale with one, two
and five names, stale with `changed: null` and with `builtAt: null`, under
a minute, 1 hour (singular), the three ranges, a `now` before `builtAt`,
and no `index` at all. `_absorb` of a failed reindex answer with `error`
sets `message` and also `indexStale` and `index`; a successful one sets
them too.

### Companion nixarchy issues (to file)

- **A. "nixarchy-search: a reindex-only mode that never opens the
  picker".** `nixarchy-search --reindex` builds the index and then opens
  `fzf`. Called without a terminal (as `nixarchy-pkg reindex` does), the
  picker fails with "inappropriate ioctl for device" and the script exits
  0, so the exit status says nothing about whether indexing worked.
  A mode that builds the index, prints nothing on success, exits non-zero
  when indexing fails, and never reaches the picker would let callers trust
  the status and drop the noise filtering. nixarchy-pkg keeps its stamp
  check either way.
- **B. "Rebuild the search index after a new system generation, in the
  background".** The index is keyed on its inputs and goes stale silently
  after any rebuild that moves nixpkgs; on one machine it was 14 days old
  with six of seven inputs changed. An optional user unit that runs the
  reindex-only mode (A) when `/run/current-system` changes, at low priority
  and never during `nixarchy-apply`, would keep it fresh. It costs about
  45 s and 5 GB of memory per run (measured), so it should be opt-in or
  deferred until the session is idle.

## Alternatives rejected

- **Compare the index age with the system generation's age.** A generation
  that did not move nixpkgs does not stale the index; the stamp already
  answers the real question.
- **Parse `index-errors.log`.** 598 of its 600 lines are warnings on a
  good run.
- **Show the age always, not only when stale.** The footer has room for one
  line; a fresh index needs no comment.
- **Recognise the format by line count alone.** A different seven inputs
  would be mis-named; the suffix check costs nothing more.
- **A format version in the stamp.** Cleaner, but needs nixarchy to write
  it; the suffix check works with every stamp already on disk.

## Risks

- **nixarchy changes the stamp's inputs.** A new count, a reordering or a
  replaced input fails the line-count or suffix check and gives
  `changed: null`: the panel says "stale" and nothing it cannot back. The
  adapter's staleness test already depends on the same seven names
  (`:260-263`), so such a change needs an adapter release anyway.
- **The no-terminal noise changes wording** (another fzf, another locale).
  The filter would let it through, and a failed reindex would show it as
  the reason. Harmless: the log path is always given. Companion issue A
  removes the need.
- **Footer width.** The longest line ("index built 14 days ago — nixpkgs
  and 4 more changed — r to rebuild") is checked against the card on
  razer; `tst_card.qml` measures the footer already.
