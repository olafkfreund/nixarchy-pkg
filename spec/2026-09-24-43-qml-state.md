# Spec: the panel's state matches what actually happened

## Design

The intent's four open questions were decided here, not by the approver.
Each is marked; gate 2 is where they can be overturned.

### 1. Closing a form mid-write

**Decision (Q1): the one-liner, not a token.** `finish()`
(`OptionForm.qml:131`) clears `open`, `option` and `path`; it also clears
`writingPath`.

The intent asked whether this leaves "same option reopened quickly"
ambiguous, and whether the codebase's `_inspectToken` pattern should be
copied. It does not, because of an interlock that already exists:
`commit()` refuses to start while `root.model.busy` (`:252`), and `busy` is
only cleared when a write answers (`:94`) or -- after this change -- when
its process exits. So a second write to the same option **cannot** be in
flight while the first is unanswered, and there is never more than one
outstanding response to disambiguate. A token would be machinery guarding
against a state the interlock already forbids.

This is worth checking rather than believing: if a reviewer can construct
two simultaneous in-flight writes, the one-liner is wrong and the token is
right.

**Decision (Q2): refresh on the late path; no message.** The guard at `:98`
currently returns before `model.refresh()` at `:112`, so a write that landed
while the form was closing leaves the panel stale. The guard becomes:

```qml
if (!root.open || root.writingPath !== root.path) {
  // The form moved on, but the write still happened -- the adapter had
  // already written the file before this answer was sent. The panel must
  // not go on showing pre-write state just because nobody is watching.
  if (data && data.ok !== false && root.model) root.model.refresh()
  return
}
```

No footer message is added. The user navigated away from that form; a
message about it would land on whatever they are doing now. `refresh()`
updates the queued count in the footer, which is the feedback that matters
and is already visible.

Together these fix both repros: after ESC the panel refreshes, and on
reopening the same option `writingPath` is `""` so the stale answer is
dropped instead of calling `finish()` on a form the user is typing into.

### 2. Naming a flake input survives a tab change

**Decision (Q3): cancel in `setTab`, and tell `Menu` it was not an ESC.**

`setTab()` (`PkgModel.qml:198`) is the one choke point -- the list's
Tab/Backtab/Left/Right (`Menu.qml:240-243`), the field's forwarding, and
`Card.qml:60-63`'s click all route through it -- so the fix belongs there
and nowhere else.

But cancelling is not enough, and the obvious shortcut is wrong. A
naming-changed watcher in `Menu.qml` would clear the search field every time
`naming` goes false, including on `Menu.qml:214` where
`search.text = pkg.cancelNaming()` deliberately **puts the flakeref back**
so a hand-typed ref is not lost. The two cancellations mean different
things:

| trigger | means | field |
| ------- | ----- | ----- |
| ESC (`Menu.qml:214`) | "I changed my mind about the name" | restore the ref |
| tab change (new) | "I have left this tab" | drop it |

So `PkgModel` gains a signal emitted only by the second:

```qml
signal namingAbandoned()

function setTab(i) {
  disarm()
  invalidateInspection()
  if (naming) { cancelNaming(); namingAbandoned() }
  ...
}
```

and `Menu.qml` connects it to clear `search.text` and the query. `ESC` is
untouched.

### 3. One `Process` shared by two readers

**`runSearch()` gets its own `Process`.** `_reader` (`PkgModel.qml:210`)
stops being shared: `refresh()` keeps it for `state`, and a new `_searcher`
takes `search`. This restores the rule the file already states at
`:208-209` and that every other operation follows -- `_writer`, `_pending`,
`_inspector`, `_apply`, `_applyTerm` each have their own.

Both feed the existing `_absorb(text, false)`, which already distinguishes a
search answer from a state answer by shape (`data.rows` vs `data.apps`,
`:236-252`), so no dispatch changes.

### 4. Processes that die without answering

**Decision (Q4): three, not a sweep.** `onExited` is added only where a
failure strands a flag that blocks later work:

| process | strands | add |
| ------- | ------- | --- |
| `OptionForm` `writeProc` | `model.busy` -> every later write refused "still writing" | yes |
| `PkgModel._writer` | `busy`, same | yes |
| `OptionForm` `describe` | the form open with no option and no error | yes |
| `_reader`, `_searcher`, `_pending`, `_inspector`, `_applyTerm` | nothing blocking | no |
| `_apply` | already has one (`:565`) | n/a |

Each clears the flag and sets an error naming the exit code. Per the
intent's constraint, unblocking is **not** reporting success: the message
says the adapter ended without answering, so nothing is known to have been
written -- the wording #28 established.

## Alternatives rejected

- **A monotonic token for `writingPath`.** Correct, and the pattern exists
  here already, but it guards a state the `busy` interlock forbids. Revisit
  if that interlock is ever removed.
- **Blocking ESC while a write is in flight.** Rejected by the intent's
  constraints: a user who presses ESC must get their form closed. The defect
  is in what happens to the response, not in the key.
- **A `Connections { onNamingChanged }` watcher in `Menu.qml`.** Smaller,
  and wrong -- it cannot tell the ESC cancellation from the tab-change one,
  so it would discard a hand-typed flakeref that ESC is specifically
  designed to preserve.
- **Guarding Tab/Backtab in `Menu.qml` instead of fixing `setTab`.** Leaves
  `Card.qml`'s tab-header click still broken, and puts the rule in one of
  three callers rather than where they all pass.
- **Stopping `_reader` before reassigning its command.** One line versus a
  new `Process`, but it makes search and state contend for one channel by
  design, and a cancelled-then-restarted read is a new race rather than a
  fixed one.
- **`onExited` on all seven processes.** Uniform, but four of them strand
  nothing, and an error path that cannot fire is a claim the next reader has
  to verify.

## Risks

- **The `busy` interlock is load-bearing for decision Q1.** If it is weaker
  than read, the one-liner is insufficient. Stated explicitly so review can
  attack it.
- **`namingAbandoned()` is a new signal for one caller.** Justified by the
  ESC/tab distinction, but it is machinery, and a reviewer may prefer the
  field simply always clearing.
- **Nothing here is caught by CI.** The QML layer has no tests and no lint
  (#44). Every check below is by hand, and a regression will ship silently.
- **Defect 3's fix changes which read wins a race**, rather than removing
  the race: a search and a state read now genuinely run at once. `_absorb`
  dispatches by shape, so both land correctly, but two answers may now
  arrive close together where one used to be dropped.
- **razer only.** Never p620.
