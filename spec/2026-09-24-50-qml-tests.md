# Spec: the QML layer is checked by something other than my eyes

## Design

All four of the intent's questions were decided here. Two of them were
**probed rather than reasoned about**, because the intent recorded them as
unknown and a spec built on a guess would be the same mistake this task
exists to stop.

### What was probed

| probe | result |
| ----- | ------ |
| A headless `TestCase` observing a `Flickable` | `contentHeight` derives from its `Column`, `clip` reads back, `contentY` is settable. **`contentHeight > height` is observable** -- the assertion that would have caught #42's overflow |
| A stub `Process` emitting `exited(code, status)` | `Connections` receives it with the code. **#43's `onExited` fix is testable** |

Both passed. Had the second failed, the suite could not protect the fix that
makes the `busy` interlock safe, and the honest answer would have been to
narrow the intent.

### 1. Scope: `PkgModel` and `Card`, not `Menu` and `OptionForm`

**Decision (Q1).** This task covers the two files that need almost nothing
faked:

- `PkgModel.qml` imports only `QtQuick` and `Quickshell.Io`, takes
  `host` and derives `script` -- **no `qs.*` at all**. It held three of
  #43's four defects.
- `Card.qml` needs `Style` and `Color` only. It held #45's arithmetic.

`Menu.qml` and `OptionForm.qml` need `Border` plus five widget stubs
(`BorderSurface`, `PanelWindow`, `TextField`, `Toggle`, `Dropdown`,
`NumberField`). Those stubs are exactly where the intent's constraint
against "a second implementation of the shell" bites hardest, and they are
most of the work for the remainder of the value.

**This leaves two things uncovered, and they are named rather than
glossed:** `OptionForm`'s stale-write defect (#43) and its `Flickable` from
#42 -- still the one unverified claim on `main`. Probe A proves the
`Flickable` *is* reachable headless, so the follow-up starts from evidence
instead of re-deriving it. A follow-up issue is opened at implementation
time, not promised vaguely here.

### 2. Stubs provide shape, never behaviour

**Decision (Q2), the line the intent asked for:** a stub declares the
**properties and signals our code binds to, and nothing else**. It models no
semantics. Where a test needs something to happen, the test makes it happen
explicitly.

`tests/qml/imports/Quickshell/Io/` provides `Process`, `StdioCollector` and
`SplitParser` as inert objects with the surface `PkgModel` uses -- `command`,
`running`, `stdout`, `onStreamFinished`, `onRead`, `exited(code, status)` --
plus two test-only helpers:

```qml
function deliver(text) { ... }   // pretend the adapter answered
function finish(code)  { ... }   // pretend the process exited
```

No stub ever runs a command, parses JSON, or decides anything. **Every
assertion is about what our code did with what it was handed**; none is
about what the stub produced. An assertion that would fail because omarchy
or Quickshell changed is a false alarm and gets deleted, per the intent.

`tests/qml/imports/qs/Commons/` provides `Style` and `Color` singletons with
the 9 and 11 members these files touch, returning plain arithmetic
(`space(v) -> round(v)`) and plain colours. Their values are **not**
asserted anywhere.

### 3. It runs in CI, as a flake check

**Decision (Q3).** It needs nothing razer has. `qt6.qtdeclarative` is
already in the CI closure for `qml-syntax` (#44), so the marginal cost is
the runtime, not a new dependency. A `qml-tests` check beside `qml-syntax`
means `nix flake check` covers it and no workflow change is needed --
the same shape #44 established.

Headless via `QT_QPA_PLATFORM=offscreen`. `qmltestrunner` exits 1 on a
failing assertion, verified, so it is a gate rather than advice.

### 4. What gets asserted

Drawn from defects that shipped, per the intent's constraint:

**`PkgModel`**
- A write answer arriving after its form moved on still refreshes, and does
  not close a form reopened on the same option (#43).
- `setTab` cancels naming and emits `namingAbandoned`, while
  `cancelNaming` alone does not (#43) -- the distinction a plain watcher
  would destroy.
- A search and a state read in flight together both land, because they are
  separate `Process`es (#43).
- A writer that exits without answering clears `busy` (#43) -- the probe
  that had to pass for this to be possible.
- `_absorb` dispatches by shape: a `rows` answer does not overwrite the
  catalogue.

**`Card`**
- The summary width is never negative.
- It accounts for the flags row and its gaps -- the N=0/N=1/N=2 arithmetic
  from #45, which was checked by eye and by cropping a screenshot.

## Alternatives rejected

- **Covering all five files now.** Five widget stubs for the remaining
  value, and the widest exposure to the "second implementation" risk.
- **A stub `Process` that models real semantics** (spawning, buffering,
  exit codes). Faithful, and a re-implementation of Quickshell that would
  itself need tests.
- **Testing through the real shell on razer.** That is what this task exists
  to stop relying on.
- **A separate workflow step rather than a flake check.** `nix flake check`
  already gates everything else here; a second entry point is a second thing
  to remember.
- **Asserting `Style.space()` or `Color.*` values.** Tempting as a
  sanity check, and precisely the false alarm the intent forbids.

## Risks

- **Stubs drift from the real Quickshell.** If `Process` gains a signal our
  code starts using, the stub will not have it and the test will pass
  against a shape that no longer exists. Mitigated by keeping stubs to the
  surface actually bound, and by `qml-syntax` and the shell itself catching
  a genuinely wrong API. Not eliminated.
- **A test can pass while the desktop is broken.** These assert logic, not
  appearance. Nothing here would have caught #38's text scale or #42's
  overflow *in situ* -- and saying so matters more than the tests do.
- **`when: windowShown` and timing.** Async assertions need
  `tryCompare`/`wait` rather than bare `compare`; a test that races will be
  flaky, and a flaky check gets ignored, which is worse than no check.
- **`Card` may not instantiate standalone.** It expects a `model` and a
  `ListView` context. If it needs more scaffolding than a `TestCase` can
  reasonably give, the `Card` half narrows to the width arithmetic in
  isolation, and that is recorded rather than worked around by changing
  `Card.qml`.

## Verification

1. `nix flake check -L` passes with `qml-tests` included.
2. **Negative, not committed:** each new assertion fails when the fix it
   guards is reverted in a scratch copy. An assertion that passes against
   the pre-fix code is worthless -- #41 already produced one of those and it
   was caught only by trying.
3. `qmltestrunner` exits **1** on that scratch copy, so the check gates.
4. The suite runs with no display, no `/etc/nixarchy`, no omarchy shell, and
   no razer -- confirmed by running it in the sandbox.
5. `tests/adapter.sh` on razer still passes, unchanged.
6. CI green, with the QML tests visible in the log rather than skipped.
