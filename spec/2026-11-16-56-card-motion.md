# Spec: the card responds to the pointer and shows work as motion, and the Selection tab loads without a binding loop

## Design

Designed on top of #55 (`fix/55-row-hierarchy-contrast`) and #60 (PR #70,
`feat/60-truthful-queue`), both merged first. `Card.qml` line numbers are
#55's (`[55:n]`); #60 adds 11 lines above the list (`rowColor`), so its
numbers below line 22 are 11 higher. `PkgModel.qml` numbers are #60's
(`[60:n]`).

**Decisions from intent approval** (the three open questions, as
recommended):

1. Order: #55, then #60, then this. The Queue tab's count is in scope.
2. `working…` stays, beside the motion. Where the motion sits is chosen in
   section 3.
3. Inspecting a flake (`inspecting`) gets the same motion as a write.

**Decisions for the owner** (not settled by the intent; chosen here,
overturn at this gate):

- **A. The busy motion is a short segment sliding along the footer's
  existing top rule** (`Card.qml` [55:389-394]). Why: the rule is already
  there, one pixel high and full width, so the motion adds no element and no
  height, and it sits directly above `working…`. With motion off, the whole
  rule turns `selectedText` instead, which still reads as "busy".
- **B. The busy motion also runs for #60's `check`** (`checkRunning`,
  about a minute). Same reason as decision 3: the user waits on it the same
  way. Not for `applying`: the apply streams its own log, which is progress.
- **C. Tab counts follow the bar badge's rule.** Selection shows its number
  whenever `state` has loaded, including 0, because an empty selection is a
  fact. Queue shows its number only when it is above 0, `?` when the queue is
  unknown after a failed read, and nothing before the first read has
  answered. A refresh keeps the last number (or `?`) until it answers,
  because #60 does not clear `queued` when a read starts
  (`PkgModel.qml` [60:465-481]). This is
  what #60's bar badge does (`Panel.qml` [60:150], [60:171]).
- **D. Label format `Selection 12`**, the count in the tab's own colour at
  the same size, one space after the name. No brackets: the tab row is
  already seven words wide.
- **E. Hover colour is `menu.selectedBackground` at half its alpha**
  (`Qt.rgba(c.r, c.g, c.b, c.a * 0.5)`, never `Qt.alpha(c, 0.5)`, which
  sets an absolute alpha and could come out stronger than the cursor). The
  shell has no hover token for menus. #55 set the precedent of deriving a
  colour from a theme token by alpha (`dim`, [55:20]), so a theme switch
  still carries it.
- **F. One PR, five commits, in this order:** #57 (section 1), hover and fade
  (section 2), busy motion (section 3), tab counts (section 4), docs and
  screenshots (section 6). #57 first because it is the smallest and every
  later test sets `tab = 2`.

### 1. #57: the scope line stops binding its height to itself

Reproduced on 2026-11-16 with `qmltestrunner` from qtdeclarative 6.12.0,
offscreen, on a minimal copy of the scope line:

| Variant | Binding loop |
| --- | --- |
| today: `Text { height: visible ? implicitHeight + 6 : 0; wrapMode: Text.Wrap }` | yes |
| `bottomPadding: 6; height: visible ? implicitHeight : 0` | yes |
| no explicit height, empty text when hidden | no, but 25 px tall when hidden |
| `Item { height: visible ? scopeText.implicitHeight + 6 : 0; Text { id: scopeText; width: parent.width } }` | **no**, 0 px when hidden |

A wrapping `Text`'s `implicitHeight` depends on its own geometry, so binding
its `height` to it loops. The fix is the last row: `scope` [55:117-128]
becomes an `Item` with the anchors, `visible` and `height`, holding the
`Text` with `width: parent.width`. Everything that anchors to `scope.bottom`
(the list [55:135], the preview [55:342]) is unchanged.

### 2. #56: hover and the cursor fade

- **Rows.** The delegate's `MouseArea` [55:161] gets `hoverEnabled: true`.
  The delegate `Rectangle`'s `color` [55:159] becomes:
  `current ? selectedBackground : rowMouse.containsMouse ? hoverBackground
  : restBackground`, with `hoverBackground` and `restBackground` as
  `readonly property color`s on `root`. `restBackground` is
  `selectedBackground` at alpha 0, not `"transparent"`: `transparent` is
  `#00000000`, and `ColorAnimation` interpolates each channel, so a fade to
  it passes through grey on a light theme (agy review). Keeping the RGB and
  moving only alpha avoids that.
  It gets `Behavior on color { enabled: !Style.reduceMotion; ColorAnimation
  { duration: Style.duration(120) } }`, so moving the cursor fades the old
  row out and the new one in, and with motion off no animation is created at
  all. 120 ms sits
  under the shell's own button fades (`WidgetButton.qml` uses
  `Style.duration(140)` and `(160)`).
- **Tabs.** The tab `MouseArea` [55:81] gets `hoverEnabled: true`. A
  non-current tab under the pointer draws its label in `fg` instead of
  `dim` [55:93]; the current tab is unchanged. Same `Behavior` on the label
  colour. New lookups inside the tab delegate go through `tabItem.`, not
  `parent.`, so `qmllint` can type them.
- Hover never sets `cursor`, `tab` or focus. A click does what it does today.
- `highlightMoveDuration: 0` [55:144] stays. The row colour is what fades;
  the view's scroll is left exactly as it is.
- No new hover state on the preview pane, the footer or the option form.

### 3. #56: busy motion

`root` gets `readonly property bool waiting: Boolean(model && (model.busy
|| model.inspecting || model.checkRunning))`. `Boolean(...)`: a null model
or a fake one missing a flag would otherwise assign `null` or `undefined`
to a `bool` and warn.

The footer's top rule [55:389-394] becomes an `Item` of the same height,
with `clip: true` so the segment never paints outside the card at either end
of its run, holding:

- the existing rule, unchanged when not waiting;
- while `waiting` and `!Style.reduceMotion`: a segment one fifth of the width,
  `color: Color.menu.selectedText`, `visible: root.waiting &&
  !Style.reduceMotion`. The animation runs a `progress` property from 0 to 1
  in `Style.duration(1100)` ms, looping (`NumberAnimation { loops:
  Animation.Infinite; running: root.waiting && !Style.reduceMotion }`), and
  the segment binds `x: -width + progress * (parent.width + width)`. Not
  animating `x` itself: a `NumberAnimation`'s `from`/`to` are read once when
  it starts, so a card created while already busy would capture a width of 0
  and a resize would not reach it (agy review). A 0-to-1 run has nothing to
  go stale;
- while `waiting` and `Style.reduceMotion`: the rule itself in
  `selectedText` at full opacity, no animation.

`running` must test `Style.reduceMotion` itself: `Style.duration()` returns
0 when motion is off, and an infinite animation of 0 ms would spin.
`working…` stays where it is [55:475], driven by `busy` as today
(decision 2).

### 4. #56: tab counts

`PkgModel.qml` gets one function beside `tabs` [60:28]:

```qml
// The number a tab label carries, or "" for none. Same rule as the bar badge.
function tabCount(i) {
  if (i === 2) return state && state.packages ? String(state.packages.length) : ""
  if (i === 6) return queued > 0 ? String(queued) : (queued === -1 && queueError ? "?" : "")
  return ""
}
```

- Selection counts `state.packages`, never `rows()`: while a query is typed,
  the tab lists search results (`indexTab && searching`, [60:121]), and the
  label must keep saying how big the selection is.
- The tab label [55:89] becomes
  `modelData + (count ? " " + count : "")`, where `count` is
  `root.model ? root.model.tabCount(tabItem.index) : ""`, so a model torn
  down before its delegates does not throw. The binding re-evaluates when
  `state` is replaced, or `queued` or `queueError` change. #60 replaces
  `state` whole on every answer (`PkgModel.qml` [60:393]); a test must do
  the same, not edit `state.packages` in place.
- No other tab gets a count. Apps and Services are catalogues; Options,
  Drafts and Flakes are short and say their length on sight.

### 5. Test stub

`tests/qml/imports/qs/Commons/Style.qml` gains what the code now binds:

```qml
property bool reduceMotion: false
function duration(ms) { return reduceMotion ? 0 : ms }
```

A writable `reduceMotion`, so a test can turn motion off. It is a singleton,
so `tst_card.qml`'s `init()` sets it back to `true` before every test: colour
checks then see the final colour at once, and a busy test that needs motion
on sets `false` itself.

### 6. Docs

`docs/img/` screenshots that show the tab row are retaken, so the labels
match. `docs/manual/the-menu.md` gets one line for the counts and one for the
busy rule. No other doc mentions hover or `working…`.

### 7. Tests

`tests/qml/tst_card.qml`. No test waits on an animation or reads a position
mid-run. Colour checks run with `Style.reduceMotion = true`, where changes
are immediate. Busy checks assert only `visible` and `running`, which do not
depend on time.

The fake model in `tst_card.qml` ([55:27-42]) has one tab and none of the new
fields. It gains the seven real tab names, `state`, `queueError`,
`inspecting`, `checkRunning` and a `tabCount(i)` that returns a fixed string
per tab, so the card's label binding is tested. The real `tabCount` is
tested in `tst_pkgmodel.qml`, which builds the real `PkgModel`.

- **#57:** `failOnWarning(/Binding loop detected/)` in the test that shows
  the Selection tab, and in a new `test_selection_tab_has_no_binding_loop`
  that sets `tab = 2`, narrows the card, and widens it again. The scope
  item's height is 0 when hidden and above 0 when shown.
- **Hover:** `mouseMove` onto row 1 while the cursor is on row 0: row 1's
  colour is `hoverBackground`, row 0's is `selectedBackground`, and
  `model.cursor` is still 0. The same for a tab: label colour `fg`, `tab`
  unchanged.
- **Busy, motion on:** with `busy`, the segment is visible and its
  animation `running`. The same for `inspecting` and `checkRunning`. Not
  busy: hidden, not running.
- **Busy, motion off:** with `busy` and `reduceMotion`, the segment is
  hidden, the animation is not running, the rule is `selectedText`, and
  `working…` still shows.
- **Counts, in the card:** the label is `<name> <tabCount(i)>`, and just
  `<name>` when `tabCount` returns "".
- **Counts, in `tst_pkgmodel.qml`:** with two packages in `state`,
  `tabCount(2)` is `"2"`, and stays `"2"` after a query whose results are
  five rows. `tabCount(6)`: `"3"` at `queued = 3`; `""` at 0 and at -1 with
  no error; `"?"` at -1 with an error. Every other tab: `""`.

## Alternatives rejected

- **A `ListView` `highlight` item with `highlightMoveDuration`.** Moves a
  bar between rows rather than fading, and #55's rows paint their own colour
  for the pills and icons inside them. The colour `Behavior` gives the fade
  with no new item.
- **Replacing `working…` with the edge.** Rejected at intent approval
  (decision 2).
- **A spinner glyph in the footer.** Needs a font glyph the theme may not
  carry, and animates text, which is harder to read than a rule.
- **A dedicated hover token from the shell.** There is none
  (`Commons/Color.qml` `menu` has `selectedBackground`, `selectedText`,
  `selectedBorder` and no hover); asking upstream for one is not needed for
  this.
- **Counts on every tab.** Apps and Services would count the catalogue,
  which is not what "how much is in it" means to the user.
- **`bottomPadding` or an empty text for #57.** Measured above: still loops,
  or leaves 25 px when hidden.

## Risks

- **Tab row width.** Two counts add up to about eight characters. On the
  narrowest card a long Selection number could crowd the last tab.
  `tst_card.qml` checks geometry for rows, not for the header; with the
  seven real tab names in the fixture, the plan adds a check that
  `header.implicitWidth <= header.width` at the width the tests already use
  (800 px). Not `header.width`: the header is anchored left and right, so
  its width always equals the card's (agy review).
- **Hover after keyboard use.** A pointer resting over the list keeps a row
  hovered while the user arrows. The cursor colour is stronger, so the two
  stay distinct; nothing moves the cursor.
- **Turning motion off mid-fade.** `enabled: !Style.reduceMotion` on the
  `Behavior` stops new fades at once; one already running finishes within
  120 ms.
- **Delegate reuse.** `ListView` creates delegates as they scroll in; a new
  delegate takes its colour without animating, which is correct.
- **#55 and #60 not merged yet.** Every change is on their code. Line numbers
  are re-checked when the plan is written.
- Light and dark themes: every colour is a token or a token at reduced alpha,
  as #55 requires.
