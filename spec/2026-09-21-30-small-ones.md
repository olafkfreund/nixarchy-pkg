# Spec: the small ones

Reviewed before writing by Codex (`gpt-6-astra`, read-only). It confirmed
items 1–4 and 6, added a panel caller to item 3, `[broken]` to item 4, and
two README contradictions (item 7), and qualified item 5.

## Design

**1. Options copy.** `Menu.qml:263-264` and `Card.qml:237` choose their
text on `indexTab`, which is true for Selection and Options alike. Options
gets its own: placeholder `search NixOS options…`, empty state `type to
search NixOS options`. Selection keeps "nixpkgs".

**2. A flag without its value.** In `cmd_search`'s loop
(`bin/nixarchy-pkg:194-195`), `--kind` and `--limit` check `[ $# -ge 2 ]`
and otherwise `die "--limit needs a value"`. Every path then prints one
object and exits 0, as the header promises.

**3. Queries starting with `-`.** `cmd_search` treats `--` as the end of
flags. The panel's `runSearch` (`PkgModel.qml:268`) sends
`search --kind … --limit … -- <query>`. Without that caller change, a
panel search for `-foo` would still fail (Codex).

**4. unfree and broken shown twice.** The installed index builder appends
` [unfree]` and ` [broken]` to the summary *and* sets the flags. The
adapter's `cmd_search` removes a trailing ` [unfree]` / ` [broken]` from
`summary` **only when the matching flag is present** (intent Q3). An old
index without structured flags keeps its only warning (Codex). Done in
the adapter's jq, not the card, so the terminal output matches.

**5. Install and `plugin validate`.** Split into what is established:

- *Confirmed:* Home Manager installs the plugin folder as a store symlink,
  and `omarchy plugin validate` refuses it.
- *Not established:* the README's claim that `rescanPlugins` won't
  reload a plugin reached through a symlink. The installed registry's
  scan (`for sub in "$dir"/*/`) follows directory symlinks, so discovery
  works. Whether already-loaded QML reloads is untested (Codex).

So:

- The README's install section says to validate the build output
  (`omarchy plugin validate "$(nix build --print-out-paths .#default)"`),
  not the installed path, and says why.
- The README's development note is corrected to what is known: validation
  refuses a symlink; reload behaviour is untested and the reliable path is
  `omarchy-restart-shell`.
- An issue is filed on **nixarchy** (intent Q1: its `programs.nixarchy.plugins`
  module produces the symlink, so the decision is nixarchy's) proposing
  that the validator follow a top-level store symlink, or the module copy.
  Nothing here migrates existing installs.

**6. Clickable tabs.** Intent Q2: yes. Each tab label in `Card.qml`
(`:47-70`) gets a `MouseArea` that calls `model.setTab(index)`. Rows are
already clickable (`Card.qml:129`), so mouse-less tabs are the
inconsistency, not the other way round. Focus afterwards follows #27's
`focusList()` via `onTabChanged`, so this lands after #27.

**7. README contradictions** (Codex):

- `README.md:81-82` says the plugin writes "nowhere else — never
  `/etc/nixos`". The Flakes tab writes `/etc/nixos/flake.nix` and its
  lock. The sentence becomes: selection files only, except the Flakes tab,
  which appends one marked line to the system flake and locks it, with a
  pointer to that section.
- `README.md:57` says `nix flake show` "needs no build". The adapter's own
  comment (`bin/nixarchy-pkg:701`) knows a flake using
  import-from-derivation can make it build, which is why there's a 120 s
  timeout. It becomes "usually needs no build".

## Alternatives rejected

- **Strip `[unfree]` in the index builder.** It is nixarchy's, and fzf's
  picker reads the same summary. Stripping in the adapter keeps both
  right.
- **Symlink-proof the plugin here** (copy on activation). The install is
  nixarchy's module; a second installer in this repo would fight it.
- **Leave the tabs keyboard-only and say so.** Rows already take clicks;
  one more `MouseArea` is cheaper than explaining the exception.

## Risks

- Item 3 changes the panel/adapter argv. Both ship together in one
  store path, so there's no version skew.
- Item 6 depends on #27 landing first.
- Item 5's nixarchy issue is outward-facing. Filed only at
  implementation, after this spec is approved.
