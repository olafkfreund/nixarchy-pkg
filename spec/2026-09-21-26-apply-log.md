# Spec: stream the apply log, as plain text, with an outcome you can see

Reviewed before writing by Codex (`gpt-6-astra`, read-only). Its findings
that changed this design were checked here first; each is marked where it
applies.

## Design

### 1. Ask nixarchy-apply instead of guessing its questions

The installed `nixarchy-apply` takes `--yes --no-preview` (checked on p620
and razer; this is upstream nixarchy #769, which `cmd_apply`'s comment is
still waiting for). `cmd_apply` runs

    nixarchy-apply --yes --no-preview

with stdin from `/dev/null`, and **deletes** everything that exists only
to cope with the questions:

- the `command -v nixarchy-preview` branch and its `n\ny\n` / `y\n` answers
  (`bin/nixarchy-pkg:1111-1116`);
- the "Not switching." check (`:1123-1133`).

The check is not only redundant: it is broken. Measured under the adapter's
own `set -euo pipefail`, `printf '%s' "$out" | grep -q "Not switching\."`
misses the phrase **50 times out of 50** once the output passes the pipe
buffer (~64 KB; a real rebuild log does): `grep -q` exits on the match,
`printf` takes SIGPIPE, `pipefail` makes the condition false, and the
adapter reports `applied`. (Codex's finding; reproduced here.) With `--yes`
there is no decline to detect, so the fix is deletion, not repair.

A nixarchy too old to know the flags answers `usage: nixarchy-apply …` on
stderr with a nonzero exit, which the normal failure path below reports
verbatim. No version probe.

### 2. Stream, stripped, with the right exit code

    set +e +o pipefail
    NO_COLOR=1 NH_ELEVATION_STRATEGY=… nixarchy-apply --yes --no-preview \
        </dev/null 2>&1 |
      awk '{ gsub(/\033\[[0-9;?]*[A-Za-z]/, ""); gsub(/\033[()][A-Za-z0-9]/, "")
             sub(/.*\r/, ""); print; fflush() }'
    local statuses=("${PIPESTATUS[@]}")
    set -e -o pipefail

- **Streaming:** `fflush()` after every line, so the panel's `SplitParser`
  gets each line as it is printed. Measured: a line printed before a 1s
  sleep arrives at 7 ms.
- **awk, not `sed -u`.** The obvious `sed -u … -e '$a\'` (append a
  newline at EOF) has to read one line ahead to know which line is last,
  so every line is held back until the next arrives. Measured: the same
  line arrived at 1007 ms. awk's `print` ends every record, including an
  unterminated last one, with a newline, so the JSON record can never be
  glued onto a log line. No lookahead.
- **Stripping** in the adapter (intent Q1), so a terminal user of
  `nixarchy-pkg apply` gets the same text. It covers CSI sequences (colour,
  cursor, the `?25l` family) and charset shifts; `sub(/.*\r/, "")` keeps
  only the last redraw of a carriage-return progress line (`50%\r100%` →
  `100%`, measured). `NO_COLOR=1` is also set (intent Q2), as a request,
  not a guarantee. The strip covers what ignores it.
- **Exit code:** `statuses[0]` is nixarchy-apply's; `statuses[1]` is
  awk's. An awk failure is reported as its own error rather than blamed on
  the build. `$?` under `pipefail` would give the rightmost failure, which
  is the wrong one (Codex).

### 3. A final record that cannot be mistaken for build output

The last line becomes

    {"nixarchyPkgApply":{"ok":true,"exit":0,"message":"applied"}}

The QML reader (`PkgModel.qml:429`) currently ends the apply on **any**
line that parses with a boolean `ok` and a numeric `exit`, and a build can
print that. It will accept only an object whose single key is
`nixarchyPkgApply`. The wrapper key is the contract; its shape is written
in the adapter header next to the other subcommands.

### 4. The panel sees the start, the stream, and the end

In `PkgModel.qml` / `Menu.qml`:

- On `a`: the log opens with one line, `starting rebuild…  ESC stops
  watching; the build carries on` (intent Q3). It says "starting", not
  "building": evaluation can run silently for tens of seconds.
- On the final record: its message is appended to the log as the last
  line (`— applied —` or `— failed: <message> —`). The log stays up until
  ESC, and the state is refreshed. Today the message is written into the
  footer, and `Menu.qml:304` hides the footer while the log is showing,
  so nobody ever sees it.
- On process exit with no final record (the adapter could not start, or
  `die()` fired before streaming: `need nixarchy-apply`), `applying` is
  cleared and the log ends `— the apply ended without a result; see
  above —`. Today `applying` stays true forever. Exit and stream drain are
  not ordered in Quickshell, so the exit handler defers one tick
  (`Qt.callLater`) and acts only if the record has not arrived by then.

## Alternatives rejected

- **Strip in QML.** Leaves `nixarchy-pkg apply` in a terminal and any
  future consumer with the escapes, and splits the contract.
- **Keep the stdin answers and fix the grep.** Keeps a guess about
  another program's prompts that has already been wrong once (#19), when
  that program now has a flag for exactly this.
- **`script -q` / a pty to get line buffering.** A pty makes nh colour
  *more* and pulls in `util-linux`'s `script` for no gain: nh already
  writes line by line to a pipe; only our `$(…)` held it back.
- **`sed -u` for the filter.** Holds each line until the next (see
  Design §2).
- **Rendering ANSI as rich text.** The log is external input; plain text
  stays the rule (`Menu.qml:329`).

## Risks

- **A nixarchy without `--yes`** fails at once with its usage line instead
  of building. That's visible and immediate, and better than the silent
  guess. All current hosts have the flags.
- **A shell restart during apply.** Quickshell kills its child processes
  when it dies (Codex, citing the Process docs). The switch itself runs
  under `systemd-run` (seen in razer's journal) and survives; the log
  does not. Not made worse by this change; noted, not fixed here.
- **Over-stripping.** awk removes only ESC-introduced sequences and
  text before a CR. Nothing else in a line changes.

## Verification

`tests/adapter.sh`, with the existing stub `nixarchy-apply` replaced by one
that:

1. **Streams:** prints `early`, sleeps 1s, prints `late`. The test reads the
   adapter's stdout line by line and asserts `early` arrived before the
   sleep ended (timestamped with `date +%s%N`). This fails on today's code;
   the current tests cannot, because they capture completed output
   (Codex).
2. **Strips:** prints `\e[1mADDED\e[0m` and `50%\r100%`; the log lines are
   exactly `ADDED` and `100%`.
3. **Passes the flags:** records its argv; asserts `--yes --no-preview` and
   an empty stdin.
4. **Exit codes:** stub exits 3 → final record `ok:false, exit:3`; stub
   exits 0 → `ok:true`.
5. **No final newline:** stub prints `last` with no `\n`; the final record
   is still alone on its own line and parses.
6. **Contract:** the last line parses as `{nixarchyPkgApply:{ok,exit,message}}`,
   and a stub line of `{"ok":true,"exit":0}` in the middle does not end the
   apply (checked by the panel run below).
7. `awk` is added to the minimal test PATH (`tests/adapter.sh:157`).

The decline tests (`:174` on) go, with the code they tested.
